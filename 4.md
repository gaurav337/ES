## 1. Time Delays in Embedded Systems: Rationale & Execution Realities
*(Slide Deck Reference: Slides 3–4)*

In embedded systems engineering, precise time intervals are mandatory for:
- **Human-Visible Indications:** Blinking LEDs (e.g., $0.5\text{ s}$ or $1\text{ s}$ cadence).
- **Physical Transducer Settling & Debouncing:** Mechanical switch contact bounces persist for $5\text{ ms} - 20\text{ ms}$; software delays filter out spurious bounces.
- **Protocol Timing:** Standard asynchronous serial bit periods, LCD HD44780 command execution delays ($37\ \mu\text{s} - 1.52\text{ ms}$), and I2C/SPI bus setup/hold times.
- **Periodic Sampling:** Sampling analog sensor voltages via ADC at fixed sample rates.

```
+--------------------------------------------------------------------------+
|                  TWO FUNDAMENTAL DELAY GENERATION APPROACHES             |
+--------------------------------------------------------------------------+
| 1. SOFTWARE DELAYS (CPU Wasting) | 2. HARDWARE TIMERS (Peripheral Driven)|
| - Implemented via loops (DJNZ)  | - Dedicated silicon counter logic     |
| - Burns 100% CPU execution power| - CPU is free to execute other code   |
| - Accuracy drifts if interrupted| - Extremely precise, jitter-free      |
+--------------------------------------------------------------------------+
```

### 1.1 Machine Cycle Physics
In the classic Intel 8051 architecture:
$$\mathbf{1 \text{ Machine Cycle (MC)} = 12 \text{ Crystal Oscillator Clock Periods}}$$
$$\mathbf{T_{\text{MC}} = \frac{12}{f_{\text{XTAL}}}}$$

```
+--------------------------------------------------------------------------+
|              MACHINE CYCLE TIMES FOR STANDARD CRYSTAL FREQUENCIES        |
+--------------------------------------------------------------------------+
| Crystal Frequency ($f_{\text{XTAL}}$) | Clock Period ($T_{\text{OSC}}$) | Machine Cycle Time ($T_{\text{MC}}$) |
| ------------------------------------ | ------------------------------- | ----------------------------------- |
| **12.0000 MHz**                      | $83.33\text{ ns}$                | $\mathbf{1.0000 \ \mu s}$            |
| **11.0592 MHz** (UART Standard)      | $90.42\text{ ns}$                | $\mathbf{1.0851 \ \mu s}$            |
| **6.0000 MHz**                       | $166.67\text{ ns}$               | $\mathbf{2.0000 \ \mu s}$            |
| **22.0000 MHz** (High-speed 8051)    | $45.45\text{ ns}$                | $\mathbf{0.5455 \ \mu s}$            |
| **22.1184 MHz** (Double Baud)        | $45.21\text{ ns}$                | $\mathbf{0.5425 \ \mu s}$            |
+--------------------------------------------------------------------------+
```

## 2. Software Delay Architectures: Single-Loop & Multi-Level Nested Loops
*(Slide Deck Reference: Slides 6–7)*

### 2.1 Single-Loop Software Delay
```assembly
DELAY:  MOV  R2, #250    ; 1 Machine Cycle  (Executed once)
LOOP:   DJNZ R2, LOOP    ; 2 Machine Cycles (Executed 250 times)
        RET              ; 2 Machine Cycles (Executed once)
```
- **Cycle Count Formulation:**
  $$\text{Total Cycles} = 1 + (250 \times 2) + 2 = 503 \text{ Machine Cycles}$$
- **Real-World Delay (at $12\text{ MHz}$, $T_{\text{MC}} = 1.0\ \mu\text{s}$):**
  $$\text{Delay} = 503 \times 1.0\ \mu\text{s} = 503\ \mu\text{s} \approx \mathbf{0.5\text{ ms}}$$
- **Hardware Boundary Limit:** Since `R2` is an 8-bit register ($0\text{ to }255$), the maximum iteration count of a single loop is $256$ (achieved by loading `#00H`).
  $$\text{Max Single-Loop Delay (12 MHz)} \approx (256 \times 2) \times 1.0\ \mu\text{s} \approx \mathbf{512\ \mu s}$$

### 2.2 Double-Nested Software Delay Loop
To generate delays in the tens or hundreds of milliseconds, an outer loop reloads the inner register:

```assembly
DELAY:  MOV  R1, #20     ; 1 Cycle  (Outer loop counter)
OUTER:  MOV  R2, #250    ; 1 Cycle  (Inner loop counter, reloaded each pass)
INNER:  DJNZ R2, INNER   ; 2 Cycles (Inner loop body)
        DJNZ R1, OUTER   ; 2 Cycles (Outer loop decrement)
        RET              ; 2 Cycles
```
- **Cycle Count Calculation:**
  $$\text{Inner Loop Duration} = 250 \times 2 = 500 \text{ Cycles}$$
  $$\text{One Outer Pass} = (\text{MOV R2}: 1) + 500 + (\text{DJNZ R1}: 2) = 503 \text{ Cycles}$$
  $$\text{Total Cycles} = (\text{MOV R1}: 1) + (20 \times 503) + (\text{RET}: 2) = 1 + 10,060 + 2 = \mathbf{10,063 \text{ Cycles}}$$
- **Delay at $12\text{ MHz}$:**
  $$\text{Delay} = 10,063 \times 1.0\ \mu\text{s} = \mathbf{10.063\text{ ms}}$$

### 2.3 Triple-Nested Software Delay Loop (Second-Scale Timing)
```assembly
; Generates approximately 0.5 second delay at 22 MHz (Endsem 2025 Q1b)
DELAY_05S:
        MOV  R3, #14     ; Outer loop counter
L3:     MOV  R2, #255    ; Middle loop counter
L2:     MOV  R1, #255    ; Inner loop counter
L1:     DJNZ R1, L1      ; Inner: 2 cycles * 255 = 510 cycles
        DJNZ R2, L2      ; Mid: (510 + 3) * 255 = 130,815 cycles
        DJNZ R3, L3      ; Outer: 130,815 * 14 = 1,831,410 cycles
        RET
```

## 3. Processor Variant Timing: Classic 12-Clock vs. High-Speed 1-Clock 8051s
*(Slide Deck Reference: Slide 5 | Slide 21 Practice Q5)*

Not all 8051 microcontrollers require 12 clock ticks per machine cycle. Modern silicon derivatives re-architected the internal pipeline:

| 8051 Variant Family | Silicon Manufacturer | Clocks per Machine Cycle | Speedup Factor at Identical Crystal Frequency |
| :--- | :--- | :---: | :---: |
| **Intel MCS-51 / Atmel AT89C51**| Intel / Microchip | **12 Clocks** | $1\times$ (Standard Baseline) |
| **Philips / NXP P89V51RD2** | NXP Semiconductors | **6 Clocks** (X2 Mode) | **$2\times$ Faster** |
| **Dallas Maxim DS89C420 / 450**| Maxim Integrated | **1 Clock** | **$12\times$ Faster** |
| **Atmel AT89LP Family** | Microchip | **1 Clock** (Single-Cycle) | **$12\times$ Faster** |

> **Slide 21 Practice Problem 5 Answer:**
> A student runs identical DJNZ delay code on an **AT89C51** ($12\text{ clocks/cycle}$) and a **DS89C450** ($1\text{ clock/cycle}$), both using a $12\text{ MHz}$ crystal.
> - On AT89C51: $T_{\text{MC}} = \frac{12}{12\text{ MHz}} = 1.0\ \mu\text{s}$.
> - On DS89C450: $T_{\text{MC}} = \frac{1}{12\text{ MHz}} = 0.0833\ \mu\text{s}$ ($83.33\text{ ns}$).
> - **The LED on the DS89C450 blinks $12\times$ FASTER** because the delay loop completes in $\frac{1}{12}\text{th}$ the real-world time!

## 4. Hardware Timers & Counters Architecture: TH0, TL0, TH1, TL1
*(Slide Deck Reference: Slide 8 | Direct Exam Relevance: Midsem 2024, 2025 & Endsem 2025)*

The 8051 integrates **two fully independent 16-bit hardware Timer/Counters**:
- **Timer 0:** Formed by two 8-bit SFR registers: **`TH0`** (High Byte, address `8CH`) and **`TL0`** (Low Byte, address `8AH`).
- **Timer 1:** Formed by two 8-bit SFR registers: **`TH1`** (High Byte, address `8DH`) and **`TL1`** (Low Byte, address `8BH`).

```
+--------------------------------------------------------------------------+
|                  8051 16-BIT HARDWARE TIMER ARCHITECTURE                 |
+--------------------------------------------------------------------------+
|                                                                          |
|       TIMER 0 REGISTER PAIR:             TIMER 1 REGISTER PAIR:          |
|    +----------------+----------------+ +----------------+----------------+|
|    |  TH0 (8 Bits)  |  TL0 (8 Bits)  | |  TH1 (8 Bits)  |  TL1 (8 Bits)  ||
|    |  Address: 8CH  |  Address: 8AH  | |  Address: 8DH  |  Address: 8BH  ||
|    +----------------+----------------+ +----------------+----------------+|
|           15 -------------- 0                 15 -------------- 0        |
|                                                                          |
+--------------------------------------------------------------------------+
```

### 4.1 Timer vs. Counter Mode
- **Timer Operation ($C/\overline{T} = 0$):** Increments on every internal machine cycle ($f_{\text{OSC}} / 12$). Used for generating precise time delays, measuring elapsed intervals, and baud rates.
- **Counter Operation ($C/\overline{T} = 1$):** Increments on every **$1$-to-$0$ negative falling edge** applied externally to pin **`P3.4` (`T0`)** for Counter 0, or pin **`P3.5` (`T1`)** for Counter 1. Used for counting external events (people entering a room, motor shaft pulses).

## 5. The TMOD Register: Bit Allocation & Operating Modes (0 to 3)
*(Slide Deck Reference: Slide 8 | Direct Examination Question: Midsem 2024 Q3a [4 Marks])*

The **TMOD (Timer Mode)** register is an 8-bit SFR at address **`89H`**.
> **CRITICAL RULE:** **TMOD is NOT bit-addressable.** You cannot write `SETB TMOD.1`. You must load the complete 8-bit byte at once (e.g., `MOV TMOD, #01H`).

```
                    TMOD REGISTER BIT ALLOCATION [89H]
      Bit:     7       6       5       4       3       2       1       0
           +-------+-------+-------+-------+-------+-------+-------+-------+
           | GATE  |  C/T  |  M1   |  M0   | GATE  |  C/T  |  M1   |  M0   |
           +-------+-------+-------+-------+-------+-------+-------+-------+
           |<------- TIMER 1 FIELD ------->|<------- TIMER 0 FIELD ------->|
```

### 5.1 Exhaustive Bit Breakdown
- **`GATE` (Hardware Gating Control):**
  - **$\text{GATE} = 0$ (Software Control):** The timer runs whenever the software run bit `TRx` is set (`TRx = 1`), regardless of external pin voltage.
  - **$\text{GATE} = 1$ (Hardware Gating):** The timer runs **ONLY while `TRx = 1` AND the external interrupt pin ($\overline{\text{INT0}}$ / $\overline{\text{INT1}}$) is held HIGH**. This is used for measuring the pulse width of external signals.
- **`C/T` (Counter/Timer Selector):**
  - **$C/\overline{T} = 0$:** Configured as a **Timer** (internal clock $f_{\text{OSC}} / 12$).
  - **$C/\overline{T} = 1$:** Configured as an **Event Counter** (clocked by external pulses on `P3.4` or `P3.5`).
- **`M1, M0` (Operating Mode Bits):**

| M1 | M0 | Operating Mode | Hardware Architecture & Behavior |
| :---: | :---: | :---: | :--- |
| **0** | **0** | **Mode 0** | **13-Bit Timer Mode:** Emulates 8048 legacy architecture. Uses all 8 bits of `THx` cascaded with the lower 5 bits of `TLx` ($2^{13} = 8192\text{ max counts}$). Rarely used in modern designs. |
| **0** | **1** | **Mode 1** | **16-Bit Timer Mode:** Cascades all 8 bits of `THx` and all 8 bits of `TLx` to form a full 16-bit counter ($2^{16} = 65,536\text{ max counts}$). Rollover from `FFFFH` to `0000H` sets overflow flag `TFx`. Must be reloaded in software after every overflow. |
| **1** | **0** | **Mode 2** | **8-Bit Auto-Reload Mode:** `TLx` functions as the 8-bit counter ($0\text{ to }255$), while `THx` permanently stores the reload value. Upon overflow of `TLx`, hardware **automatically reloads the contents of `THx` into `TLx`** and sets `TFx`. Ideal for UART baud rate generation and square waves! |
| **1** | **1** | **Mode 3** | **Split Timer Mode:** Timer 0 is split into two independent 8-bit timers (`TL0` using `TR0`/`TF0`, and `TH0` using `TR1`/`TF1`). Timer 1 is stopped and holds its count. |

## 6. The TCON Register: Control Bits, Overflow Flags & Edge/Level Triggers
*(Direct Examination Question: Midsem 2024 Q3a [4 Marks])*

The **TCON (Timer Control)** register is an 8-bit SFR at address **`88H`**.
> **CRITICAL RULE:** **TCON IS bit-addressable.** You can directly manipulate individual bits (`SETB TR0`, `CLR TF1`, `SETB IT1`).

```
                    TCON REGISTER BIT ALLOCATION [88H]
  Bit:     7       6       5       4       3       2       1       0
Symbol:   TF1     TR1     TF0     TR0     IE1     IT1     IE0     IT0
Address: 8FH     8EH     8DH     8CH     8BH     8AH     89H     88H
```

### 6.1 Exhaustive Functional Description of TCON Bits

| Bit | Symbol | Bit Addr | Function & Operational Logic |
| :---: | :---: | :---: | :--- |
| **TCON.7** | **`TF1`** | `8FH` | **Timer 1 Overflow Flag:** Set to `1` by hardware upon Timer 1 roll-over. Cleared automatically by hardware when the CPU vectors to the Timer 1 ISR; must be cleared by software in polling mode (`CLR TF1`). |
| **TCON.6** | **`TR1`** | `8EH` | **Timer 1 Run Control Bit:** Set to `1` by software to start Timer 1; cleared to `0` by software to halt Timer 1. |
| **TCON.5** | **`TF0`** | `8DH` | **Timer 0 Overflow Flag:** Set to `1` by hardware upon Timer 0 roll-over. Cleared automatically when CPU vectors to Timer 0 ISR; cleared by software in polling mode (`CLR TF0`). |
| **TCON.4** | **`TR0`** | `8CH` | **Timer 0 Run Control Bit:** Set to `1` by software to start Timer 0; cleared to `0` by software to halt Timer 0. |
| **TCON.3** | **`IE1`** | `8BH` | **External Interrupt 1 Edge Flag:** Set to `1` by hardware when an edge is detected on $\overline{\text{INT1}}$. Cleared automatically by hardware when ISR is executed. |
| **TCON.2** | **`IT1`** | `8AH` | **External Interrupt 1 Trigger Type Selector:** `IT1 = 1` configures $\overline{\text{INT1}}$ as **Falling Edge-Triggered**; `IT1 = 0` configures $\overline{\text{INT1}}$ as **Low Level-Triggered**. |
| **TCON.1** | **`IE0`** | `89H` | **External Interrupt 0 Edge Flag:** Set to `1` by hardware when an edge is detected on $\overline{\text{INT0}}$. Cleared automatically when ISR executes. |
| **TCON.0** | **`IT0`** | `88H` | **External Interrupt 0 Trigger Type Selector:** `IT0 = 1` configures $\overline{\text{INT0}}$ as **Falling Edge-Triggered**; `IT0 = 0` configures $\overline{\text{INT0}}$ as **Low Level-Triggered**. |

## 7. Hardware Timer Programming & Exact Count Calculations
*(Direct Examination Relevance: Endsem 2025 Q3a [8 Marks])*

### 7.1 Mathematical Derivation Steps for Mode 1 (16-Bit Timer)
To produce a desired time delay $T_{\text{delay}}$:
1. **Find Timer Clock Frequency and Period:**
   $$f_{\text{TIMER}} = \frac{f_{\text{XTAL}}}{12}, \qquad T_{\text{TIMER}} = \frac{1}{f_{\text{TIMER}}} = \frac{12}{f_{\text{XTAL}}}$$
2. **Calculate Required Count Steps ($N$):**
   $$N = \frac{T_{\text{delay}}}{T_{\text{TIMER}}}$$
3. **Calculate Initial 16-Bit Value to Load ($M$):**
   $$M = 65,536 - N$$
4. **Convert $M$ to Hexadecimal:**
   $$M = \text{High Byte (TH)} \ \text{and} \ \text{Low Byte (TL)}$$

```
+--------------------------------------------------------------------------+
|                  ENDSEM 2025 Q3(a) VERIFIED NUMERICAL TRACE              |
+--------------------------------------------------------------------------+
| Parameter                   | Value at 11.0592 MHz | Value at 22.1184 MHz|
| --------------------------- | -------------------- | ------------------- |
| Machine Cycle Frequency     | 921.6 kHz            | 1.8432 MHz          |
| Timer Clock Period          | 1.0851 us            | 0.5425 us           |
| Overflow Time (TH=3C, TL=AF)| 54.25 ms             | 27.13 ms            |
| 1 ms Delay Initial Value    | FC66H (64,614)       | F8CDH (63,693)      |

```

## 8. Waveform Generation: Square Waves & Arbitrary Duty Cycles
*(Direct Exam Relevance: Midsem 2024 Q3b & Endsem 2025 Q3c)*

A rectangular waveform consists of an **ON-time ($T_{\text{HIGH}}$)** and an **OFF-time ($T_{\text{LOW}}$)**.
$$\text{Total Time Period } T = T_{\text{HIGH}} + T_{\text{LOW}}$$
$$\text{Frequency } f = \frac{1}{T}, \qquad \text{Duty Cycle} = \frac{T_{\text{HIGH}}}{T} \times 100\%$$

### 8.1 Generating an Asymmetric Square Wave with ONE Subroutine (Midsem 2024 Q3b)
*Problem:* Generate a wave on all pins of Port 1 with **$T_{\text{ON}} = 10\text{ ms}$** and **$T_{\text{OFF}} = 5\text{ ms}$** at $11.0592\text{ MHz}$ using **only one delay subroutine**.

#### Step 1: Clock & Count Calculations
- $T_{\text{TIMER}} = \frac{12}{11.0592\text{ MHz}} \approx 1.08507 \ \mu\text{s}$.
- **For OFF-time ($5\text{ ms}$):**
  $$N_{\text{OFF}} = \frac{5\text{ ms}}{1.08507\ \mu\text{s}} \approx 4608 \text{ counts}$$
  $$\text{Value} = 65536 - 4608 = 60928_{10} = \mathbf{EE00H} \implies \text{TH0} = \text{EEH}, \ \text{TL0} = 00\text{H}$$
- **For ON-time ($10\text{ ms}$):**
  $$N_{\text{ON}} = \frac{10\text{ ms}}{1.08507\ \mu\text{s}} \approx 9216 \text{ counts}$$
  $$\text{Value} = 65536 - 9216 = 56320_{10} = \mathbf{DC00H} \ (\text{or } \text{DBFFH}) \implies \text{TH0} = \text{DBH}, \ \text{TL0} = \text{FFH}$$

#### Step 2: Optimal Assembly Implementation
```assembly
; Generates 10 ms ON / 5 ms OFF rectangular wave on Port 1
        ORG 0000H
        MOV TMOD, #01H        ; Timer 0, Mode 1 (16-bit)
BACK:   MOV TL0, #00H
        MOV TH0, #0EEH        ; Load 5 ms count
        MOV P1, #00H          ; Output LOW (OFF time)
        ACALL DELAY
        MOV TL0, #0FFH
        MOV TH0, #0DBH        ; Load 10 ms count
        MOV P1, #0FFH         ; Output HIGH (ON time)
        ACALL DELAY
        SJMP BACK

        ORG 0300H
DELAY:  SETB TR0              ; Start Timer 0
AGAIN:  JNB  TF0, AGAIN       ; Wait until Timer 0 overflows (TF0=1)
        CLR  TR0              ; Stop Timer 0
        CLR  TF0              ; Clear overflow flag
        RET
        END
```

## 9. Mode 2 Factor Decomposition Technique (When Delay Exceeds 256 Cycles)
*(Direct Examination Question: Midsem 2025 Q4 [10 Marks])*

### 9.1 The Engineering Dilemma
Timer Mode 2 is an **8-bit auto-reload timer**. The maximum number of counts it can accumulate before overflowing is:
$$N_{\text{max}} = 256 \text{ counts}$$
At $f_{\text{XTAL}} = 22\text{ MHz}$, $T_{\text{MC}} = \frac{12}{22\text{ MHz}} = 0.5455 \ \mu\text{s}$.
$$\text{Maximum Possible Delay in Mode 2} = 256 \times 0.5455\ \mu\text{s} \approx \mathbf{139.6\ \mu s}$$
- This corresponds to a minimum single-pulse frequency of:
  $$f_{\text{min}} = \frac{1}{2 \times 139.6\ \mu\text{s}} \approx \mathbf{3.58\text{ kHz}}$$
- **The Problem:** The examiner asks you to generate a **$1\text{ kHz}$ square wave** using **Timer Mode 2**!
  - Half-period required ($T_{\text{half}}$) $= \frac{1}{2 \times 1\text{ kHz}} = 0.5\text{ ms} = 500\ \mu\text{s}$.
  - Total machine cycles needed:
    $$N_{\text{required}} = \frac{0.5\text{ ms}}{0.5455\ \mu\text{s}} \approx \mathbf{915 \text{ cycles}}$$
  - Since $915 > 256$, **it is physically impossible to achieve this in a single Mode 2 overflow!**

### 9.2 The Factor Decomposition Solution
We decompose the 915 cycles into an integer product of an 8-bit timer count and a software register multiplier:
$$915 = 183 \times 5$$
1. Program the auto-reload register **`TH0` with $183$ counts**:
   $$\text{TH0} = 256 - 183 = 73_{10} = \mathbf{49H}$$
   $$\text{Hardware Delay} = 183 \times 0.5455\ \mu\text{s} \approx 99.8\ \mu\text{s}$$
2. Use a CPU register (e.g., `R0`) to repeat this hardware delay **$5$ times**:
   $$\text{Total Delay} = 5 \times 99.8\ \mu\text{s} \approx \mathbf{499\ \mu s} \approx \mathbf{0.5\text{ ms!}}$$

```assembly
; Complete 1 kHz Waveform Generator in Mode 2 at 22 MHz
        ORG 0000H
        MOV TMOD, #02H        ; Timer 0 in Mode 2 (8-bit auto-reload)
RPT:    CPL P1.2              ; Toggle target pin P1.2
        MOV R0, #05           ; Multiplier = 5
        MOV TH0, #49H         ; Auto-reload count = 256 - 183 = 49H
        SETB TR0              ; Start Timer 0
AGAIN:  JNB TF0, AGAIN        ; Wait for 183-count overflow
        CLR TF0               ; Clear overflow flag (TH0 automatically reloads to TL0!)
        DJNZ R0, AGAIN        ; Repeat 5 times
        CLR TR0               ; Halt timer
        SJMP RPT              ; Repeat forever
        END
```

## 10. Hardware Event Counters: Theory & Real-World System Design
*(Direct Exam Relevance: Midsem 2024 Q3c & Midsem 2025 Q2)*

When configured as a Counter ($C/\overline{T} = 1$), the 8051 increments `TLx` upon every negative falling edge ($1 \to 0$) applied to the external pin:
- Counter 0 listens to **Pin `P3.4` (`T0`)**.
- Counter 1 listens to **Pin `P3.5` (`T1`)**.

### 10.1 Auditorium 500-Guest Counter System (Midsem 2024 Q3c)
*Specification:* An auditorium has a maximum capacity of 500 guests. An optical turnstile sensor at the entrance pulses pin `P3.4`. Count each person entering and output the 16-bit binary count to Port 2 (lower byte) and Port 1 (higher byte).

```
+--------------------------------------------------------------------------+
|                  AUDITORIUM GUEST COUNTER SCHEMATIC                      |
+--------------------------------------------------------------------------+
|  OPTICAL ENTRANCE SENSOR ---> Pin P3.4 (T0 Counter Input)                |
|                                                                          |
|  8051 MICROCONTROLLER                                                    |
|  - Counter 0 configured in Mode 1 (16-bit Counter)                       |
|  - Continuous display of TL0 on Port 2 (Bits 0-7)                        |
|  - Continuous display of TH0 on Port 1 (Bits 8-15)                       |
|  - Terminal Capacity Check: 500 guests = 01F4H                           |
+--------------------------------------------------------------------------+
```

```assembly
; 8051 Event Counter for 500 Guests Auditorium
        ORG 0000H
        MOV TMOD, #05H        ; Timer 0: Mode 1 (16-bit) and Counter Mode (C/T = 1)
        MOV TL0, #00H         ; Initialize counter low byte
        MOV TH0, #00H         ; Initialize counter high byte
        SETB P3.4             ; Configure P3.4 as input pin!
        SETB TR0              ; Start counting external pulses

DISPLAY:
        MOV A, TL0            ; Read lower 8 bits of count
        MOV P2, A             ; Output to Port 2 display
        MOV A, TH0            ; Read upper 8 bits of count
        MOV P1, A             ; Output to Port 1 display

        ; Check if capacity limit of 500 (01F4H) has been reached:
        CJNE A, #01H, DISPLAY ; If TH0 != 01H, continue counting
        MOV A, TL0
        CJNE A, #0F4H, DISPLAY; If TL0 != F4H, continue counting

        ; Limit of 500 reached! Halt entrance turnstile:
        CLR TR0               ; Stop counter
HALT:   SJMP HALT             ; Halt further entry
        END
```

## 11. 8051 Serial Communication (UART): Frame Architecture & SCON Register
*(Direct Examination Relevance: Endsem 2025 Q4 [10 Marks])*

The 8051 features an integrated full-duplex Universal Asynchronous Receiver/Transmitter (UART).
- **Serial Frame Format (Mode 1):** 1 Start Bit (logic 0), 8 Data Bits (transmitted LSB first), 1 Stop Bit (logic 1). Total frame length = **10 bits**.

```
                           UART 10-BIT SERIAL FRAME
       +-------+----+----+----+----+----+----+----+----+-------+
  Line | START | D0 | D1 | D2 | D3 | D4 | D5 | D6 | D7 | STOP  | Line
  Idle |   0   |LSB |    |    |    |    |    |    |MSB |   1   | Idle
  (1)  +-------+----+----+----+----+----+----+----+----+-------+ (1)
```

### 11.1 The SCON Register [98H] (Bit-Addressable)
```
                    SCON REGISTER BIT MAP [98H]
  Bit:     7       6       5       4       3       2       1       0
Symbol:   SM0     SM1     SM2     REN     TB8     RB8     TI      RI
Address: 9FH     9EH     9DH     9CH     9BH     9AH     99H     98H
```
- **`SM0, SM1` (Serial Mode Selectors):**
  - `0, 1` $\implies$ **Mode 1: 8-bit UART, variable baud rate set by Timer 1** (Standard mode used in 99% of applications).
- **`REN` (Receiver Enable):** Set to `1` by software to permit incoming data reception on `RXD`.
- **`TI` (Transmit Interrupt Flag):** Set to `1` by hardware as soon as the last bit (Stop bit) of a character is transmitted. **Must be cleared by software (`CLR TI`)**.
- **`RI` (Receive Interrupt Flag):** Set to `1` by hardware as soon as a complete byte plus Stop bit is received. **Must be cleared by software (`CLR RI`)**.

## 12. Baud Rate Engineering: The PCON Register & SMOD Doubler Bit
*(Direct Examination Questions: Endsem 2025 Q4a, Q4c [5 Marks])*

In 8051 serial communication, **Timer 1 configured in Mode 2 (8-bit auto-reload)** acts as the baud rate clock generator.

```
       BAUD RATE GENERATION CLOCK PATH:
       Crystal Oscillator (11.0592 MHz)
                    |
                    v
              [/ 12 Divider]  --> Machine Cycle Clock (921.6 kHz)
                    |
                    v
              [/ 32 Divider]  --> UART Base Frequency (28,800 Hz)
                    |
                    v
          [x 2 Multiplier if SMOD=1]
                    |
                    v
          [Timer 1 Mode 2 Overflow (256 - TH1)]
                    |
                    v
               FINAL BAUD RATE
```

### 12.1 The Master Baud Rate Formula
$$\mathbf{\text{Baud Rate} = \frac{2^{\text{SMOD}}}{32} \times \frac{f_{\text{XTAL}}}{12 \times (256 - \text{TH1})}}$$
where **`SMOD`** is bit 7 of the **PCON (Power Control) register (address `87H`)**.

### 12.2 Standard TH1 Calculation at $11.0592\text{ MHz}$
The crystal $11.0592\text{ MHz}$ was specifically chosen because:
$$\frac{11.0592\text{ MHz}}{12 \times 32} = \mathbf{28,800\text{ Hz}}$$
This divides evenly by standard baud rates ($9600, 4800, 2400, 1200$)!

#### Case 1: When $\text{SMOD} = 0$ (Default on Reset)
$$\text{Baud Rate} = \frac{28,800}{256 - \text{TH1}} \implies 256 - \text{TH1} = \frac{28,800}{\text{Baud Rate}}$$

| Desired Baud Rate | Calculation ($256 - \text{TH1}$) | Decimal TH1 | Hexadecimal TH1 Value |
| :---: | :---: | :---: | :---: |
| **9600** | $28,800 / 9600 = 3$ | $256 - 3 = 253$ | **`FDH`** (`-3`) |
| **4800** | $28,800 / 4800 = 6$ | $256 - 6 = 250$ | **`FAH`** (`-6`) |
| **2400** | $28,800 / 2400 = 12$| $256 - 12 = 244$| **`F4H`** (`-12`) |
| **1200** | $28,800 / 1200 = 24$| $256 - 24 = 232$| **`E8H`** (`-24`) |

#### Case 2: When $\text{SMOD} = 1$ (Baud Rate Doubled)
$$\text{UART Base Frequency} = 28,800 \times 2 = \mathbf{57,600\text{ Hz}}$$
- **For Baud Rate = 9600:**
  $$256 - \text{TH1} = \frac{57,600}{9600} = 6 \implies \text{TH1} = 256 - 6 = 250_{10} = \mathbf{FAH} \ (\mathbf{-6})$$
- **For Baud Rate = 4800:**
  $$256 - \text{TH1} = \frac{57,600}{4800} = 12 \implies \text{TH1} = 256 - 12 = 244_{10} = \mathbf{F4H} \ (\mathbf{-12})$$
- **Endsem 2025 Q4c Special Case ($\text{SMOD}=1, \text{TH1}=-3$):**
  $$\text{Baud Rate} = \frac{57,600}{3} = \mathbf{19,200\text{ Baud}}$$
  $$19,200_{10} = \mathbf{4B00H} \implies \text{Port 1 (Low Byte)} = \mathbf{00H}, \quad \text{Port 2 (High Byte)} = \mathbf{4BH}$$

## 13. Interrupt Programming: Vector Table, IE Register & IP Priorities
*(Slide Deck Reference & Exam Relevance: Endsem 2025 Q5)*

An **Interrupt** is an asynchronous hardware event that suspends the main program execution and diverts CPU control to a designated **Interrupt Service Routine (ISR)**.

```
+--------------------------------------------------------------------------+
|                  8051 HARDWARE INTERRUPT VECTOR TABLE                    |
+--------------------------------------------------------------------------+
| Interrupt Source                | Vector Address | Flag Bit | Clear Mech |
| ------------------------------- | :------------: | :------: | :--------- |
| **Power-On Reset**              |    `0000H`     |   None   | Automatic  |
| **External Interrupt 0 (INT0)** |    `0003H`     |   IE0    | Auto by HW |
| **Timer 0 Overflow (TF0)**      |    `000BH`     |   TF0    | Auto by HW |
| **External Interrupt 1 (INT1)** |    `0013H`     |   IE1    | Auto by HW |
| **Timer 1 Overflow (TF1)**      |    `001BH`     |   TF1    | Auto by HW |
| **Serial Port (TI or RI)**      |    `0023H`     |  TI / RI | **MANUAL!**|
+--------------------------------------------------------------------------+
```

### 13.1 The IE (Interrupt Enable) Register [A8H] (Bit-Addressable)
```
                    IE REGISTER BIT ALLOCATION [A8H]
  Bit:     7       6       5       4       3       2       1       0
Symbol:   EA      --      ET2     ES      ET1     EX1     ET0     EX0
Address: AFH     AEH     ADH     ACH     ABH     AAH     A9H     A8H
```
- **`EA` (Global Enable):** Master switch. Must be set to `1` for any interrupt to fire.
- **`ES`:** Enables Serial Port interrupt (`TI`/`RI`).
- **`ET1` / `ET0`:** Enables Timer 1 / Timer 0 overflow interrupt.
- **`EX1` / `EX0`:** Enables External Hardware Interrupt 1 / Interrupt 0.

## 14. Edge vs. Level Triggering & Interrupt Service Routine (ISR) Architecture
*(Direct Examination Question: Endsem 2025 Q5a [10 Marks])*

### 14.1 Trigger Modes for $\overline{\text{INT0}}$ and $\overline{\text{INT1}}$
Controlled by bits `IT0` and `IT1` in the `TCON` register:
- **Level-Triggered (`ITx = 0`):** Interrupt triggers as long as the pin is held at a low logic level ($0\text{V}$). If the external hardware does not release the pin before `RETI`, the interrupt immediately retriggers!
- **Edge-Triggered (`ITx = 1`):** Interrupt triggers strictly on the **falling edge ($1 \to 0$ transition)**. The 8051 sets `IEx` and clears it automatically when entering the ISR.

### 14.2 Endsem 2025 Q5a Solved: Square Wave with Frequency $f/8$ of INT1 Signal
*Problem Statement:* Generate a square wave on pin `P1.2` whose frequency is $\frac{1}{8}\text{th}$ of the signal applied at the `INT1` pin without using polling.

#### Theoretical Insight:
- One complete period of a square wave consists of **one HIGH half-cycle and one LOW half-cycle** (2 toggles).
- To produce an output frequency $f_{\text{out}} = \frac{f_{\text{in}}}{8}$, the output time period must be $8\times$ the input period.
- Therefore, the pin must **toggle once every 4 input pulses** ($4 \text{ pulses high} + 4 \text{ pulses low} = 8 \text{ input pulses total}!$).

```assembly
; Generates f/8 frequency square wave on P1.2 driven by INT1 interrupts
        ORG 0000H
        LJMP MAIN

; Hardware Interrupt Vector for INT1 (Address 0013H)
        ORG 0013H
        LJMP X1ISR

; Main Setup Program
        ORG 0030H
MAIN:   SETB TCON.2           ; IT1 = 1: Configure INT1 as falling edge-triggered
        MOV  R2, #04H         ; Initialize pulse counter to 4
        MOV  IE, #84H         ; EA = 1 (Bit 7), EX1 = 1 (Bit 2) --> 1000 0100B = 84H
HERE:   SJMP HERE             ; Idle background loop (CPU does not poll!)

; Interrupt Service Routine for INT1
        ORG 0100H
X1ISR:  DJNZ R2, SKIP         ; Decrement pulse count; skip toggle if not zero
        CPL  P1.2             ; Toggle output pin P1.2!
        MOV  R2, #04H         ; Reload pulse counter for next half-cycle
SKIP:   RETI                  ; Return from Interrupt (restores priority logic!)
        END
```

## 15. Solutions to Slide 4 Practice Problems & Advanced Exam Scenarios

### Slide 4 Practice Problem 1
*Generate a 100 ms square wave on pin P1.5 using nested software delay loop at 11.0592 MHz crystal.*
- $T_{\text{MC}} = 1.0851 \ \mu\text{s}$.
- Half period (time between toggles) for 100 ms square wave: $T_{\text{half}} = 50\text{ ms} = 50,000\ \mu\text{s}$.
- Machine cycles required: $N = \frac{50,000}{1.0851} \approx 46,079\text{ cycles}$.
- Nested loop design: Outer count $R2 = 180$, Inner count $R1 = 128 \implies 180 \times 128 \times 2 = 46,080\text{ cycles}$!
```assembly
BACK:   CPL P1.5
        MOV R2, #180
O_LP:   MOV R1, #128
I_LP:   DJNZ R1, I_LP
        DJNZ R2, O_LP
        SJMP BACK
```

### Slide 4 Practice Problem 2
*Explain difference between `MOV A, 30H` and `MOV A, @R0` (given `R0 = 30H`). Do both read the same RAM value? Why does one take more code bytes?*
- **Both read the exact same RAM value** stored at memory address `30H`.
- `MOV A, 30H` uses **Direct Addressing** $\implies$ requires **2 bytes** (`[E5H] [30H]`) because the 8-bit RAM address is encoded directly within the instruction.
- `MOV A, @R0` uses **Register-Indirect Addressing** $\implies$ requires only **1 byte** (`[E6H]`) because the pointer register `R0` is encoded within the 1-byte opcode.

### Slide 4 Practice Problem 3
*Compute bit address of RAM byte 25H, bit 5. Write instruction to set that bit.*
- Formula: $\text{Bit Address} = (\text{Byte Address} - 20\text{H}) \times 8 + \text{Bit Position}$.
- $\text{Bit Address} = (25\text{H} - 20\text{H}) \times 8 + 5 = (5 \times 8) + 5 = 40 + 5 = 45_{10} = \mathbf{2DH}$.
- Symbolic instruction: `SETB 25H.5`
- Numeric instruction: `SETB 2DH`
