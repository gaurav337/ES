## 1. Sequential Execution vs. Program Flow Control
*(Slide Deck Reference: Slide 2)*

In standard microcontroller operation, instruction execution is strictly **sequential**:
1. The **Program Counter (PC)** holds the 16-bit ROM memory address of the next opcode byte to be fetched.
2. During the instruction fetch phase, the hardware CPU automatically increments the PC by the length of the currently fetched instruction ($1, 2, \text{ or } 3\text{ bytes}$).
3. Execution flows linearly: $\text{Instruction } 1 \to \text{Instruction } 2 \to \text{Instruction } 3 \dots$

```
NORMAL SEQUENTIAL FLOW:
PC: 0000H  [ MOV A, #55H ]  (2 bytes)  --> PC auto-increments to 0002H
PC: 0002H  [ MOV R0, A   ]  (1 byte)   --> PC auto-increments to 0003H
PC: 0003H  [ ADD A, #10H ]  (2 bytes)  --> PC auto-increments to 0005H

ALTERED FLOW VIA BRANCH / JUMP:
PC: 0005H  [ SJMP TARGET ]  (2 bytes)  --> PC loaded with TARGET address!
     |
     +-------------------------------> Branches to TARGET (e.g., 0020H)
PC: 0020H  [ TARGET: MOV P1, A ]
```

Real-world embedded systems cannot rely solely on sequential execution. Embedded applications require:
- **Repetition (Loops):** Periodically polling sensors, scanning keypads, or creating time delays.
- **Decision-Making (Conditional Branching):** Taking alternate algorithmic paths based on sensor input, arithmetic flags, or register values.
- **Modularity (Subroutines / Function Calls):** Reusing identical code blocks (e.g., display routines, mathematical functions) from multiple program locations without duplicating ROM code.

## 3. Unconditional Jumps: SJMP, AJMP, LJMP & JMP @A+DPTR
*(Slide Deck Reference: Slides 4–8 | Direct Exam Relevance: Midsem 2025 Q5b)*

An unconditional jump alters the Program Counter to a specified target address **regardless of any arithmetic condition or status flag**. The 8051 provides four distinct instructions, each optimized for a specific memory scope:

```
+--------------------------------------------------------------------------+
|                     UNCONDITIONAL JUMP INSTRUCTION RANGE                 |
+--------------------------------------------------------------------------+
| SJMP  | Relative Range: -128 to +127 bytes from (PC + 2)  | 2 Bytes Size |
| AJMP  | Absolute Range: Within current 2 KB Page (11-bit) | 2 Bytes Size |
| LJMP  | Long Range: Full 64 KB Code Space (0000H - FFFFH) | 3 Bytes Size |
| JMP   | Indirect Jump: PC = A + DPTR (Jump Table lookup)   | 1 Byte Size  |
+--------------------------------------------------------------------------+
```

### 3.1 SJMP — Short Jump (Relative Addressing)
- **Syntax:** `SJMP label`
- **Machine Code Format:** `[ Opcode = 80H ] [ 8-bit Signed Relative Offset ]`
- **Size & Timing:** **2 Bytes**, **2 Machine Cycles** ($24\text{ oscillator clock periods}$).
- **Range:** Relative branch spanning from **$-128\text{ bytes}$** (backward) to **$+127\text{ bytes}$** (forward) relative to the address of the *next* instruction.
- **Architectural Operation:**
  $$\text{PC}_{\text{target}} = \text{PC}_{\text{next}} + \text{rel\_offset}$$
- **When to Use:** Standard localized loops, jumping over short conditional blocks, and infinite loops (`SJMP $`).

### 3.2 AJMP — Absolute Jump (2 KB Page Addressing)
- **Syntax:** `AJMP label`
- **Machine Code Format:** `[ a10 a9 a8 0 0 0 0 1 ] [ a7 a6 a5 a4 a3 a2 a1 a0 ]`
- **Size & Timing:** **2 Bytes**, **2 Machine Cycles**.
- **Range:** Within the same **2 KB memory page** ($2048\text{ bytes}$).
- **Architectural Mechanics:**
  - The 8051 code memory ($64\text{ KB}$) is partitioned into 32 distinct pages of 2 KB each:
    - Page 0: `0000H` – `07FFH`
    - Page 1: `0800H` – `0FFFH`
    - ...
    - Page 31: `F800H` – `FFFFH`
  - When `AJMP` executes, the upper 5 bits of the Program Counter ($\text{PC}_{15} - \text{PC}_{11}$) are left untouched.
  - The lower 11 bits ($\text{PC}_{10} - \text{PC}_0$) are replaced by the 11-bit address $a_{10}-a_0$ encoded in the instruction:
    $$\text{PC}_{\text{new}} = (\text{PC}_{\text{next}} \ \& \ \text{F800H}) \ | \ (\text{Address}_{10-0})$$
- **Restriction:** The target label **must reside within the exact same 2 KB page** as the instruction following the AJMP. Crossing a 2 KB page boundary generates an assembler error.

### 3.3 LJMP — Long Jump (Direct 16-Bit Addressing)
- **Syntax:** `LJMP 16-bit_address`
- **Machine Code Format:** `[ Opcode = 02H ] [ Target Address High Byte ] [ Target Address Low Byte ]`
- **Size & Timing:** **3 Bytes**, **2 Machine Cycles**.
- **Range:** Anywhere within the complete **64 KB Program ROM** (`0000H` to `FFFFH`).
- **Architectural Operation:** The full 16-bit address is directly loaded into the Program Counter register pair ($\text{PCH}$ and $\text{PCL}$):
  $$\text{PC} \leftarrow \text{target\_address}_{15-0}$$
- **Standard Use:** Placed at hardware reset and interrupt vector locations (e.g., `ORG 0000H; LJMP MAIN`) to branch past the interrupt vector table.

### 3.4 JMP @A+DPTR — Indexed Jump
- **Syntax:** `JMP @A+DPTR`
- **Size & Timing:** **1 Byte**, **2 Machine Cycles**.
- **Operation:** Computes target address as $\text{PC} \leftarrow \text{A} + \text{DPTR}$.
- **Application:** Essential for implementing multi-way branching (C-style `switch/case` statements) and lookup state-machine dispatch tables.

### 3.5 Rigorous Comparison Table (SJMP vs. AJMP vs. LJMP)

| Instruction | Full Technical Name | Addressing Mode | Size | Machine Cycles | Jump Target Reach | Opcode Encoding |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `SJMP` | Short Jump | Relative | **2 Bytes** | **2 Cycles** | $-128\text{ to }+127\text{ bytes}$ from next PC | `80H rel` |
| `AJMP` | Absolute Jump | Block / Page (11-bit) | **2 Bytes** | **2 Cycles** | Within current $2\text{ KB}$ Page | `a10..a8 00001B a7..a0` |
| `LJMP` | Long Jump | Absolute 16-bit | **3 Bytes** | **2 Cycles** | Full $64\text{ KB}$ code space | `02H addr15..8 addr7..0` |

## 4. Mathematical Mechanics of Relative Jump Target Offsets
*(Slide Deck Reference: Slide 5 | Direct Examination Relevance: Midsem 2024 Q2b)*

In 8051 assembly, all short relative jumps (`SJMP`, `DJNZ`, `CJNE`, `JZ`, `JC`, etc.) encode the target address as an **8-bit signed two's complement integer** ($\text{rel\_offset}$).

### 4.1 The Fundamental Formula
$$\text{Relative Offset} = \text{Target Address} - \text{Address of Next Instruction}$$
where:
$$\text{Address of Next Instruction} = \text{Current Instruction Address} + \text{Length of Current Instruction}$$

### 4.2 Two's Complement Range
An 8-bit signed integer spans:
$$-128_{10} \ (\text{80H}) \le \text{Offset} \le +127_{10} \ (\text{7FH})$$
- Offset of `00H`: Jumps to the immediate next instruction (does not loop, effectively a 2-cycle NOP).
- Offset of `FEH` ($-2_{10}$): When applied to a 2-byte instruction like `SJMP $`, it branches back to the start of the `SJMP` instruction itself (creating an infinite freeze loop).

### 4.3 Detailed Case Studies (Midsem Examination Problem Walkthroughs)

#### Case 1: Forward Jump Calculation
Consider the assembly fragment:
```assembly
Line  PC    Opcode  Instruction
01    0010  80 ??   SJMP TARGET
02    0012  74 55   MOV A, #55H
03    0014  F5 90   MOV P1, A
04    0016  04      TARGET: INC A
```
- $\text{Current Instruction Address} = 0010\text{H}$.
- Instruction length of `SJMP` = 2 bytes $\implies \text{Next Instruction PC} = 0010\text{H} + 2 = 0012\text{H}$.
- $\text{Target Address} = 0016\text{H}$.
- $\text{Offset} = 0016\text{H} - 0012\text{H} = +04\text{H} = +4_{10}$.
- Positive offset: in hex, it is simply `04H`.
- Assembler machine code emitted: `80 04`.

#### Case 2: Backward Jump Calculation (The Midsem 2024 Exam Problem!)
In **Midsem 2024 Q2b Line 10**, students were asked:
```assembly
Line  PC    Opcode   Mnemonic  Operand
10    0012  80 EC    SJMP      BACK
...
02    0000  74 55    BACK:     MOV A, #55H
```
*How is `80 EC` derived?*
1. Current instruction `SJMP BACK` is at address `0012H`.
2. Length of `SJMP` is 2 bytes.
3. Therefore, $\text{Address of Next Instruction} (\text{PC}_{\text{next}}) = 0012\text{H} + 0002\text{H} = 0014\text{H}$.
4. Target address `BACK` is at `0000H`.
5. Compute raw difference:
   $$\text{Offset} = \text{Target} - \text{PC}_{\text{next}} = 0000\text{H} - 0014\text{H} = -0014\text{H} = -20_{10}$$
6. Convert $-20_{10}$ to 8-bit Two's Complement:
   - Positive magnitude $20_{10} = 0001 \ 0100_2$
   - One's Complement (invert all bits) = $1110 \ 1011_2$
   - Add 1:
     $$\begin{array}{r@{\quad}l}
       1110 \ 1011_2 \\
     + 0000 \ 0001_2 \\
     \hline
       1110 \ 1100_2 & = \mathbf{ECH}
     \end{array}$$
7. The relative offset byte is **`ECH`**. Hence, the machine code is **`80 EC`**!

## 5. Conditional Jumps: Flags, Accumulator, and Bit-Level Branching
*(Slide Deck Reference: Slides 9–11)*

Conditional jumps execute the branch to the target address **only if the specified condition evaluates to TRUE**. If FALSE, execution falls through sequentially to the next instruction.

```
+--------------------------------------------------------------------------+
|                     8051 CONDITIONAL JUMP SUMMARY                        |
+--------------------------------------------------------------------------+
| JZ   label  | Jump if Accumulator (A) == 00H    | Evaluates ACC directly |
| JNZ  label  | Jump if Accumulator (A) != 00H    | Evaluates ACC directly |
| JC   label  | Jump if Carry Flag (CY) == 1      | Evaluates PSW.7 (CY)   |
| JNC  label  | Jump if Carry Flag (CY) == 0      | Evaluates PSW.7 (CY)   |
| JB   b, rel | Jump if Bit == 1                  | Evaluates Bit directly |
| JNB  b, rel | Jump if Bit == 0                  | Evaluates Bit directly |
| JBC  b, rel | Jump if Bit == 1, then CLEAR Bit  | Atomic test-and-clear  |
+--------------------------------------------------------------------------+
```

> **Crucial Architectural Note (Exam Trap):** In many processors (like x86 or ARM), `JZ` checks an ALU Zero Flag ($Z$) in the status register. In the **8051 architecture, there is NO Zero Flag in the PSW register!** The 8051 hardware evaluates the 8 physical flip-flops of the **Accumulator register ($A$) directly**. If all 8 bits of $A$ are zero, `JZ` branches.

### 5.1 Code Demonstrations

#### JZ / JNZ (Zero Branching on Accumulator)
```assembly
        MOV A, #25H
        SUBB A, #25H      ; A becomes 00H
        JZ  RESULT_ZERO   ; Branch taken because A == 00H
        MOV R0, #01H      ; Skipped
        SJMP EXIT
RESULT_ZERO:
        MOV R0, #00H
EXIT:   NOP
```

#### JC / JNC (Carry-Flag Branching)
Used after multi-byte addition/subtraction or arithmetic shift operations:
```assembly
        MOV A, #0FFH
        ADD A, #01H       ; 0FFH + 01H = 100H --> A = 00H, CY = 1
        JC  CARRY_FOUND   ; Branch TAKEN because CY == 1
        MOV R1, #00H      ; Skipped
        SJMP DONE
CARRY_FOUND:
        MOV R1, #01H      ; Executes!
DONE:   NOP
```

## 6. Bit-Based Jumps: JB, JNB, and Atomic JBC
*(Slide Deck Reference: Slides 12–13)*

The 8051 is renowned in industry as a "Boolean Processor" because it can directly test and manipulate individual bits in internal RAM and SFRs.

```
       TESTING INDIVIDUAL BITS:
       JB  bit, target   --> If bit == 1, Jump
       JNB bit, target   --> If bit == 0, Jump
       JBC bit, target   --> If bit == 1, CLEAR bit to 0, then Jump!
```

### 6.1 Real-World Interfacing with `JB` and `JNB`
```assembly
; Task: Read tactile push-button switch connected to P1.0. 
; If switch is pressed (Logic 1), turn on buzzer on P2.7. If 0, turn off buzzer.
CHECK_SW:
        JB  P1.0, BUZZER_ON   ; Jump if P1.0 is HIGH
        CLR P2.7              ; Switch is LOW: Turn OFF buzzer
        SJMP CHECK_SW         ; Continuous polling loop
BUZZER_ON:
        SETB P2.7             ; Turn ON buzzer
        SJMP CHECK_SW
```

### 6.2 The Power of `JBC` (Jump if Bit Set and Clear)
- **Syntax:** `JBC bit, label`
- **Operation:**
  1. Inspects the addressed bit.
  2. If $\text{bit} == 1$: The hardware CPU **automatically clears the bit to 0** and loads the target address into the PC.
  3. If $\text{bit} == 0$: The bit remains unchanged, and execution continues sequentially.
- **Why JBC is Critical in Real-Time Systems:**
  - Provides an **atomic Test-and-Clear** operation.
  - Used extensively when servicing hardware interrupt or timer overflow flags without race conditions:
    ```assembly
    WAIT_TIMER:
            JBC TF0, SERVICE_TIMER  ; If TF0=1, hardware atomically CLEARS TF0 to 0 and jumps!
            SJMP WAIT_TIMER
    ```

## 7. Loop Architectures: DJNZ Mechanics and Limits
*(Slide Deck Reference: Slides 14–16)*

### 7.1 DJNZ (Decrement and Jump if Not Zero)
- **Concept:** In high-level languages, loops require decrementing a variable, performing a comparison against zero, and branching (`x--; if(x != 0) goto loop;`).
- The 8051 unifies this into a **single 2-machine cycle instruction**: `DJNZ`.

```
                    DJNZ EXECUTION FLOWCHART
                             |
                     +---------------+
                     | Rn = Rn - 1   |  (or direct RAM byte)
                     +---------------+
                             |
                      /-------------\
                     /   Is Value    \
                    <   Equal to 0?   >
                     \               /
                      \-------------/
                       /           \
                 NO   /             \  YES
                     v               v
             Branch to TARGET     Fall through to
             (Load PC + rel)      Next Instruction
```

### 7.2 Two Syntax Variations
1. **Register Form:** `DJNZ Rn, label` (where $n = 0 \text{ to } 7$).
   - Size: **2 Bytes** (`[ 1 1 0 1 1 r r r ] [ rel ]`).
   - Timing: **2 Machine Cycles**.
2. **Direct Address Form:** `DJNZ direct, label`.
   - Size: **3 Bytes** (`[ Opcode = D5H ] [ direct RAM address ] [ rel ]`).
   - Timing: **2 Machine Cycles**.
   - Allows using any internal RAM memory location (e.g., `DJNZ 30H, LOOP`) as a loop counter without wasting a working register!

### 7.3 Maximum Iteration Capacity of a Single DJNZ Loop
- An 8051 register is 8 bits wide $\implies$ max unsigned integer value is $255_{10}$ (`FFH`).
- **If initialized with `00H`:**
  ```assembly
  MOV R0, #00H
  LOOP: NOP
        DJNZ R0, LOOP
  ```
  - When `DJNZ` decrements `00H`, it wraps around via underflow to `FFH` ($255_{10}$).
  - The loop continues decrementing until it hits `00H`.
  - Therefore, initializing a register to `00H` executes the loop **$256$ times**!
- **Theoretical Maximum:** A single 8-bit register loop cannot exceed **256 iterations**.

## 8. Nested Loops, Infinite Loops & Cycle-Accurate Delay Principles
*(Slide Deck Reference: Slides 17–19 | Direct Exam Relevance: Endsem 2025 Q1b)*

### 8.1 Nested Loops (Multiplying Iteration Counts)
To achieve thousands or millions of iterations for software time delays, loops are nested hierarchically:

```assembly
; Triple-nested delay structure
        MOV R2, #10       ; Outer loop counter (10 passes)
OUTER:  MOV R1, #200      ; Middle loop counter (200 passes)
MID:    MOV R0, #250      ; Inner loop counter (250 passes)
INNER:  DJNZ R0, INNER    ; Runs 250 times
        DJNZ R1, MID      ; Runs 200 * 250 = 50,000 times
        DJNZ R2, OUTER    ; Runs 10 * 50,000 = 500,000 times!
```

### 8.2 Infinite Loops
An infinite loop halts linear program termination in bare-metal embedded firmware:
```assembly
HERE:   SJMP HERE     ; Option 1: Standard label jump
        SJMP $        ; Option 2: Assembler shorthand ($ represents current PC)
```

## 9. The CJNE Instruction & The Carry (CY) Flag Rule
*(Slide Deck Reference: Slides 20–21 | Direct Examination Relevance: Endsem 2025 Q1c [6 Marks])*

The `CJNE` (**Compare and Jump if Not Equal**) instruction is one of the most powerful and heavily tested instructions in the 8051 architecture.

### 9.1 Syntax Forms, Size and Timing

| Syntax Form | Description | Size | Machine Cycles |
| :--- | :--- | :--- | :--- |
| `CJNE A, #data, rel` | Compare Accumulator with immediate 8-bit data | **3 Bytes** | **2 Cycles** |
| `CJNE A, direct, rel` | Compare Accumulator with direct RAM location | **3 Bytes** | **2 Cycles** |
| `CJNE Rn, #data, rel` | Compare Register Rn with immediate 8-bit data | **3 Bytes** | **2 Cycles** |
| `CJNE @Ri, #data, rel`| Compare RAM byte pointed to by Ri with immediate | **3 Bytes** | **2 Cycles** |

### 9.2 The Golden Carry Flag Rule of CJNE
Under the hood, `CJNE Destination, Source, target` performs a non-destructive hardware subtraction:
$$\text{Internal Temp} = \text{Destination} - \text{Source}$$
- Neither the Destination operand nor the Source operand is modified!
- If $\text{Destination} \ne \text{Source}$: The jump to `target` is taken.
- If $\text{Destination} == \text{Source}$: Fall through to next instruction.
- **Carry Flag (CY) Behavior:**
  $$\begin{cases} 
  \mathbf{CY = 1} & \text{if } \text{Destination} < \text{Source} \quad (\text{Borrow occurs!}) \\ 
  \mathbf{CY = 0} & \text{if } \text{Destination} \ge \text{Source} \quad (\text{No borrow occurs}) 
  \end{cases}$$

```
+--------------------------------------------------------------------------+
|                  THE GOLDEN CJNE CARRY FLAG RULE                         |
+--------------------------------------------------------------------------+
|  Destination < Source  ===>  CY = 1  (Needs borrow)                      |
|  Destination >= Source ===>  CY = 0  (No borrow)                         |
+--------------------------------------------------------------------------+
```

### 9.3 Endsem 2025 Q1c Complete Verified Solutions (All 6 Cases)
*Question: Indicate the status of the CY flag after CJNE is executed in each of the following cases:*

1. **Case (i):**
   ```assembly
   MOV A, #25H
   CJNE A, #44H, OVER
   ```
   - $\text{Destination} = 25\text{H}$, $\text{Source} = 44\text{H}$.
   - Since $25\text{H} < 44\text{H}$, a borrow is required.
   - **Status of CY = 1** (Jump taken).

2. **Case (ii):**
   ```assembly
   MOV A, #0FFH
   CJNE A, #6FH, NEXT
   ```
   - $\text{Destination} = \text{FFH} \ (255_{10})$, $\text{Source} = 6\text{FH} \ (111_{10})$.
   - Since $\text{FFH} \ge 6\text{FH}$, no borrow is generated.
   - **Status of CY = 0** (Jump taken).

3. **Case (iii):**
   ```assembly
   MOV A, #34
   CJNE A, #34, NEXT
   ```
   - $\text{Destination} = 34_{10}$, $\text{Source} = 34_{10}$.
   - Since $\text{Destination} == \text{Source}$, no borrow is generated.
   - **Status of CY = 0** (Jump NOT taken; falls through).

4. **Case (iv):**
   ```assembly
   MOV R1, #0
   CJNE R1, #0, NEXT
   ```
   - $\text{Destination} = 0$, $\text{Source} = 0$.
   - Identical values $\implies$ no borrow.
   - **Status of CY = 0** (Jump NOT taken).

5. **Case (v):**
   ```assembly
   MOV R5, #54H
   CJNE R5, #0FFH, NEXT
   ```
   - $\text{Destination} = 54\text{H}$, $\text{Source} = \text{FFH}$.
   - Since $54\text{H} < \text{FFH}$, a borrow is generated.
   - **Status of CY = 1** (Jump taken).

6. **Case (vi):**
   ```assembly
   MOV A, #0AAH
   ANL A, #55H
   CJNE A, #00, NEXT
   ```
   - $\text{AAH} = 1010 \ 1010_2$, $55\text{H} = 0101 \ 0101_2$.
   - Bitwise AND: $\text{AAH} \ \text{AND} \ 55\text{H} = 0000 \ 0000_2 = 00\text{H}$.
   - Destination $A = 00\text{H}$, Source $= 00_{10} = 00\text{H}$.
   - Since $00\text{H} == 00\text{H}$, they are equal.
   - **Status of CY = 0** (Jump NOT taken).

## 10. Subroutines and Call Instructions: ACALL vs. LCALL
*(Slide Deck Reference: Slides 22–26)*

A **Subroutine** is a self-contained, reusable block of instructions engineered to execute a common recurring operation (e.g., generating delay, floating-point math, sending a byte to LCD).

### 10.1 Why Use Subroutines?
- **ROM Code Conservation:** The code is written once in ROM memory and called hundreds of times from different points, drastically saving program space.
- **Structured Modular Architecture:** Simplifies debugging, testing, and team firmware development.

### 10.2 Architectural Comparison: ACALL vs. LCALL

```
+--------------------------------------------------------------------------+
|                     ACALL vs. LCALL ARCHITECTURAL MAP                    |
+--------------------------------------------------------------------------+
| ACALL (Absolute Call) | Range: Current 2 KB Page | Size: 2 Bytes | 2 Cyc |
| LCALL (Long Call)     | Range: Entire 64 KB Space| Size: 3 Bytes | 2 Cyc |
+--------------------------------------------------------------------------+
```

| Technical Feature | ACALL (Absolute Call) | LCALL (Long Call) |
| :--- | :--- | :--- |
| **Instruction Size** | **2 Bytes** | **3 Bytes** |
| **Execution Time** | **2 Machine Cycles** | **2 Machine Cycles** |
| **Address Scope** | Restricted to the **same 2 KB page** as the instruction following the ACALL. | Full **64 KB Program ROM** (`0000H` – `FFFFH`). |
| **Address Bits Encoded**| 11-bit target address embedded within opcode byte. | Full 16-bit target address in bytes 2 and 3. |
| **Stack Activity** | Pushes 16-bit return address onto stack. | Pushes 16-bit return address onto stack. |

## 11. Hardware Stack Mechanics During Subroutine Invocation (CALL & RET)
*(Slide Deck Reference: Slides 27–28 | Direct Examination Relevance: Endsem 2025 Q1a)*

The **Stack** is a dedicated Last-In-First-Out (LIFO) memory structure residing in internal RAM, tracked by the 8-bit **Stack Pointer (SP)**.

### 11.1 Step-by-Step Hardware Execution of `LCALL SUB1`
Suppose an `LCALL SUB1` instruction is located at address `0100H`, calling a subroutine at `0500H`. The next instruction in the main program is at `0103H` (since LCALL is a 3-byte instruction). Assume that prior to the call, $\text{SP} = 07\text{H}$.

```
BEFORE CALL:                   DURING LCALL 0500H:
PC = 0100H                     1. CPU fetches 3 bytes of LCALL.
SP = 07H                          PC increments to 0103H (Return Address!)
                               2. SP increments: SP = 08H
                                  RAM[08H] = 03H  (Lower byte of PC, PCL)
                               3. SP increments: SP = 09H
                                  RAM[09H] = 01H  (Upper byte of PC, PCH)
                               4. PC loaded with target: PC = 0500H
```

```
STACK MEMORY LAYOUT AFTER CALL:
RAM Address      Content
09H --------->   01H  (PCH)  <--- Current SP = 09H
08H --------->   03H  (PCL)
07H --------->   [Previous data]
```

### 11.2 Step-by-Step Hardware Execution of `RET`
When the subroutine reaches the `RET` instruction:
1. The CPU reads the byte from the address currently pointed to by SP and loads it into **$\text{PCH}$** (Program Counter High):
   $$\text{PCH} \leftarrow \text{RAM}[\text{SP}]; \quad \text{SP} \leftarrow \text{SP} - 1$$
2. The CPU reads the next byte and loads it into **$\text{PCL}$** (Program Counter Low):
   $$\text{PCL} \leftarrow \text{RAM}[\text{SP}]; \quad \text{SP} \leftarrow \text{SP} - 1$$
3. Program Counter now holds `0103H`.
4. $\text{SP}$ has returned to its original value of `07H`.
5. Execution smoothly resumes at address `0103H`!

> **CRITICAL PROFESSOR RULE:** PUSH pushes the **LOW byte of PC first**, then the **HIGH byte**. RET pops the **HIGH byte first**, then the **LOW byte**. This preserves the correct 16-bit address!

## 12. Subroutine Return vs. Interrupt Return: RET vs. RETI
*(Slide Deck Reference: Slide 29 | Direct Exam Relevance: Midsem & Endsem Question papers)*

Students routinely make the catastrophic error of writing `RET` at the end of an Interrupt Service Routine (ISR). In university exams, this costs complete marks!

```
+--------------------------------------------------------------------------+
|                             RET vs. RETI                                 |
+--------------------------------------------------------------------------+
| Feature               | RET (Subroutine Return) | RETI (Interrupt Return)|
| --------------------- | ----------------------- | ---------------------- |
| Primary Purpose       | Exits ordinary function | Exits an ISR           |
| Pops PC from Stack    | YES (2 bytes: PCH, PCL) | YES (2 bytes: PCH, PCL)|
| Clears Interrupt Flip-| NO                      | YES! Clears internal   |
| Flop in Hardware      |                         | interrupt-in-service   |
| Allows Lower/Equal    | Irrelevant              | CRITICAL: Without RETI,|
| Priority Interrupts   |                         | no future interrupts of |
| to fire               |                         | equal/lower level fire!|
+--------------------------------------------------------------------------+
```

### Why using `RET` inside an ISR breaks the embedded system:
When a hardware interrupt occurs, the 8051 sets an internal hardware **interrupt-in-progress flip-flop** to block lower or equal-priority interrupts from interrupting the ISR.
- The `RETI` instruction performs two actions:
  1. Pops the return address from the stack into the PC.
  2. **Resets the internal interrupt flip-flop**, re-enabling the interrupt subsystem.
- If you use `RET` instead of `RETI`, the return address will be popped, but **the internal interrupt flip-flop remains permanently set**. As a result, the microcontroller will **never service any future interrupts of that priority level again**!

#### Detailed Line-by-Line Technical Analysis:
1. **Line 10 (`SJMP BACK`):**
   - Address of instruction = `0012H`. Size = 2 bytes $\implies \text{Next PC} = 0014\text{H}$.
   - Target `BACK` = `0000H`.
   - $\text{Offset} = 0000\text{H} - 0014\text{H} = -20_{10} = \mathbf{ECH}$. Emits: `80 EC`.
2. **Line 17 (`DJNZ R5, AGAIN`):**
   - Address of instruction = `0308H`. Size = 2 bytes $\implies \text{Next PC} = 030AH$.
   - Target `AGAIN` = `0308H`.
   - $\text{Offset} = 0308\text{H} - 030A\text{H} = -2_{10}$.
   - $+2 = 00000010_2 \implies \text{1's complement} = 11111101_2 \implies \text{2's complement} = 11111110_2 = \mathbf{FEH}$.
   - Opcode for `DJNZ R5` is `DDH`. Emits: `DD FE`.
3. **Line 18 (`DJNZ R4, NEXT`):**
   - Address of instruction = `030AH`. Size = 2 bytes $\implies \text{Next PC} = 030CH$.
   - Target `NEXT` = `0306H`.
   - $\text{Offset} = 0306\text{H} - 030C\text{H} = -6_{10}$.
   - $+6 = 00000110_2 \implies \text{1's complement} = 11111001_2 \implies \text{2's complement} = 11111010_2 = \mathbf{FAH}$.
   - Opcode for `DJNZ R4` is `DCH`. Emits: `DC FA`.
