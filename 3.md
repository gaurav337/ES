## 1. Assembly Language Toolchain & File Generation Workflow
*(Slide Deck Reference: Slides 3–7)*

Assembly language is the lowest human-readable symbolic representation of a microcontroller's native binary instruction set.

```
                           ASSEMBLY TOOLCHAIN
                                   |
                         +-------------------+
                         | SOURCE CODE (.asm)|  Created by human programmer
                         +-------------------+
                                   |
                          [ 8051 ASSEMBLER ]   e.g., ASEM-51, Keil A51
                                   |
                  +----------------+----------------+
                  |                                 |
         +-----------------+               +-----------------+
         | OBJECT FILE     |               | LIST FILE       |
         | (.obj)          |               | (.lst)          |
         | Raw opcodes &   |               | Human-readable  |
         | relocatable code|               | memory map & hex|
         +-----------------+               +-----------------+
                  |
             [ LINKER ]  e.g., Keil BL51 (Combines multiple .obj + libraries)
                  |
         +-----------------+
         | ABSOLUTE FILE   |
         | (.abs)          |
         +-----------------+
                  |
           [ OH51 CONVERTER ]
                  |
         +-----------------+
         | INTEL HEX FILE  |
         | (.hex)          | ---> Burned into ROM via EPROM Programmer / ISP
         +-----------------+
```

### 1.1 The Generated Files & Their Specific Roles
- **`.asm` (Source File):** The raw ASCII source file created in a text editor containing mnemonics, operands, labels, and directives.
- **`.obj` (Object File):** Machine language binary representations of opcodes and data bytes, ready for linkage. Not directly human-readable.
- **`.lst` (List File):** An assembler-generated human-readable file containing:
  - Source line numbers
  - Exact Program Counter (PC) hexadecimal memory addresses
  - Machine code opcodes and immediate bytes generated
  - The original assembly source line
  - A complete **Symbol Table** documenting all labels and their absolute address bindings.
- **`.hex` (Intel HEX File):** Standard ASCII representation of hexadecimal machine code partitioned into records (Record Type, Byte Count, Address, Data, Checksum). Fed directly to device programmers or bootloaders to flash the microcontroller's ROM.

## 2. Structure of an Assembly Instruction & Assembler Directives
*(Slide Deck Reference: Slides 4, 10–12)*

### 2.1 Anatomy of an Assembly Statement
An 8051 assembly statement adheres to a standard 4-field structure:
$$[\text{LABEL:}] \quad \mathbf{MNEMONIC} \quad [\text{OPERAND(S)}] \quad [;\text{COMMENT}]$$

```assembly
AGAIN:  MOV  A, R5      ; Copy contents of R5 into Accumulator
```
- **Label:** An optional symbolic name representing the memory address of the instruction. Must terminate with a colon (`:`).
- **Mnemonic:** The operation code (e.g., `MOV`, `ADD`, `CJNE`, `SJMP`).
- **Operands:** Target and source arguments separated by a comma (Destination, Source).
- **Comment:** Begins with a semicolon (`;`). Ignored by the assembler.

### 2.2 Instructions vs. Assembler Directives
Students frequently confuse these two concepts on university exams:
- **Instruction:** Translates directly into machine-executable binary opcodes stored in ROM that the CPU executes at runtime (e.g., `MOV A, #55H`, `ADD A, R0`).
- **Assembler Directive (Pseudo-op):** A command addressed to the **assembler tool itself** during translation. Generates zero CPU runtime machine instructions (e.g., `ORG`, `EQU`, `END`).

### 2.3 Essential 8051 Assembler Directives
1. **`ORG` (Origin):** Sets the assembler's internal location counter. Tells the assembler at which ROM memory address to place the following instructions or data.
   ```assembly
   ORG 0000H    ; Reset vector
   LJMP MAIN
   ORG 0030H    ; Main program starts at 0030H
   MAIN: MOV A, #0FFH
   ```
2. **`DB` (Define Byte):** Allocates and initializes 8-bit constants in ROM.
   ```assembly
   ORG 0400H
   LOOKUP: DB 25H, 62H, 3FH, 52H    ; Stores 4 numerical bytes
   MSG:    DB 'HELLO 8051', 0       ; Stores ASCII string terminated with null
   ```
3. **`DW` (Define Word):** Allocates 16-bit constants (2 bytes) in ROM, stored in high-byte/low-byte order.
4. **`EQU` (Equate):** Defines a symbolic constant without allocating memory.
   ```assembly
   COUNT EQU 25
   MOV R2, #COUNT    ; Assembler replaces COUNT with 25 (#19H)
   ```
5. **`END`:** Informs the assembler that the source file is finished. Any text after `END` is completely ignored.

## 3. The Program Counter (PC) & 64 KB Code Memory Organization
*(Slide Deck Reference: Slides 8–9)*

- The **Program Counter (PC)** is a **16-bit register** that points to the memory address of the next instruction byte to be fetched from code ROM.
- Because it is 16 bits wide, the 8051 can address up to:
  $$2^{16} = 65,536\text{ bytes} = 64\text{ Kilobytes}$$
  spanning hexadecimal addresses **`0000H` to `FFFFH`**.
- Upon hardware reset, the PC is unconditionally loaded with **`0000H`**.

```
+--------------------------------------------------------------------------+
|                     8051 64 KB CODE MEMORY (ROM) MAP                     |
+--------------------------------------------------------------------------+
| 0000H - 0002H | Power-On Reset Vector (3 bytes: typically LJMP MAIN)     |
| 0003H - 000AH | External Hardware Interrupt 0 (INT0) Vector              |
| 000BH - 0012H | Timer 0 Overflow Interrupt (TF0) Vector                  |
| 0013H - 001AH | External Hardware Interrupt 1 (INT1) Vector              |
| 001BH - 0022H | Timer 1 Overflow Interrupt (TF1) Vector                  |
| 0023H - 002AH | Serial Port (UART) Interrupt (TI/RI) Vector              |
| 002BH - 0FFFH | On-Chip Internal ROM (Standard 8051: 4 KB total)        |
| 1000H - FFFFH | External Off-Chip Program ROM (Available when EA=1)      |
+--------------------------------------------------------------------------+
```

## 4. Program Status Word (PSW) Register & Arithmetic Flags
*(Slide Deck Reference: Slides 13–14 | Direct Exam Relevance: Midsem 2024 Q1b)*

The **PSW (Program Status Word)** is an 8-bit Special Function Register (SFR at address `D0H`) that reflects the arithmetic status of the CPU and selects the active register bank.

```
                    PSW (PROGRAM STATUS WORD) REGISTER [D0H]
  Bit:     7       6       5       4       3       2       1       0
Symbol:   CY      AC      F0     RS1     RS0      OV      --       P
Address: D7H     D6H     D5H     D4H     D3H     D2H     D1H     D0H
```

### 4.1 Exhaustive Bit Directory

| Bit | Symbol | Bit Addr | Name | Detailed Functional Behavior |
| :---: | :---: | :---: | :--- | :--- |
| **PSW.7** | **CY** | `D7H` | **Carry Flag** | Set to `1` whenever an arithmetic addition generates a carry out of bit $D_7$, or subtraction generates a borrow into $D_7$. Also serves as the 1-bit accumulator for Boolean operations. |
| **PSW.6** | **AC** | `D6H` | **Auxiliary Carry** | Set to `1` if an addition generates a carry out of bit $D_3$ into bit $D_4$ (lower nibble to higher nibble). Used exclusively by the `DA A` (Decimal Adjust) instruction for BCD arithmetic. |
| **PSW.5** | **F0** | `D5H` | **User Flag 0** | General-purpose status bit available for programmer software flags. |
| **PSW.4** | **RS1** | `D4H` | **Register Bank Select 1** | Most significant bit of Register Bank selector. |
| **PSW.3** | **RS0** | `D3H` | **Register Bank Select 0** | Least significant bit of Register Bank selector. |
| **PSW.2** | **OV** | `D2H` | **Overflow Flag** | Set to `1` whenever a signed arithmetic operation yields a result exceeding 8-bit two's complement capacity ($-128 \text{ to } +127$). |
| **PSW.1** | **--** | `D1H` | **User Reserved** | Undefined bit reserved for future hardware derivatives. |
| **PSW.0** | **P** | `D0H` | **Parity Flag** | Automatically set/cleared by hardware in every machine cycle to reflect the parity of Accumulator $A$: **$P = 1$ if $A$ contains an ODD number of 1s**, and **$P = 0$ if $A$ contains an EVEN number of 1s**. |

## 5. The OV (Overflow) Flag Mechanics in Signed Arithmetic
*(Direct Examination Question: Midsem 2024 Q1b [3 Marks])*

In 8-bit signed arithmetic:
- Positive numbers: $0000 \ 0000_2 \ (0)$ to $0111 \ 1111_2 \ (+127)$.
- Negative numbers (2's complement): $1000 \ 0000_2 \ (-128)$ to $1111 \ 1111_2 \ (-1)$.

Bit $D_7$ acts as the sign bit:
- $D_7 = 0 \implies \text{Positive}$
- $D_7 = 1 \implies \text{Negative}$

### 5.1 The Exact Mathematical Conditions for OV Setting
In an 8-bit signed operation, an arithmetic overflow occurs when the true mathematical result exceeds the representable range $[-128, +127]$. 

In hardware, the 8051 ALU detects this by evaluating carries at the sign boundary:
$$\mathbf{OV = C_6 \oplus C_7}$$
where $C_6$ is the carry from bit $D_6$ to bit $D_7$, and $C_7$ is the carry out of bit $D_7$ (the standard Carry flag `CY`).

The **OV flag is set to 1** if either of the following two mutually exclusive conditions occurs:
1. **Condition I:** There is a carry from bit $D_6$ into bit $D_7$ ($C_6 = 1$), but **no carry out of bit $D_7$** ($C_7 = 0$, so $\text{CY} = 0$).
2. **Condition II:** There is a carry out of bit $D_7$ ($C_7 = 1$, so $\text{CY} = 1$), but **no carry from bit $D_6$ into bit $D_7$** ($C_6 = 0$).

```
+--------------------------------------------------------------------------+
|                  THE OVERFLOW (OV) HARDWARE CRITERIA                     |
+--------------------------------------------------------------------------+
|  C6 (Carry D6->D7)  |  C7 (Carry out of D7, CY)  |  OV Flag Status       |
| ------------------- | -------------------------- | --------------------- |
|          0          |              0             |      OV = 0           |
|          0          |              1             |      OV = 1 (ERR!)    |
|          1          |              0             |      OV = 1 (ERR!)    |
|          1          |              1             |      OV = 0           |
+--------------------------------------------------------------------------+
```

### 5.2 Arithmetic Examples Demonstrating OV
#### Example A: Adding Two Large Positive Numbers (Overflow!)
$$+96_{10} \ (60\text{H}) + +80_{10} \ (50\text{H}) = +176_{10} \quad (\text{Exceeds } +127!)$$
$$\begin{array}{r@{\quad}l@{\quad}l}
  & 0110 \ 0000_2 & (60\text{H} = +96) \\
+ & 0101 \ 0000_2 & (50\text{H} = +80) \\
\hline
  & 1011 \ 0000_2 & (\text{B0H} = -80 \text{ in signed representation!})
\end{array}$$
- Look at the carries:
  - Carry from $D_6$ to $D_7$: $1 + 1 = 0$ with Carry = **1** ($C_6 = 1$).
  - Carry out of $D_7$: $0 + 0 + 1 (\text{carry}) = 1$ with Carry out = **0** ($C_7 = 0$).
- $C_6 \ne C_7 \implies \mathbf{OV = 1}$. The result wrapped into negative territory!

#### Example B: Adding Two Negative Numbers
$$-120_{10} \ (88\text{H}) + -10_{10} \ (\text{F6H}) = -130_{10} \quad (\text{Underflows } -128!)$$
- Generates $C_6 = 0$ and $C_7 = 1 \implies \mathbf{OV = 1}$.

## 6. Internal Data RAM Structure (128 Bytes: 00H–7FH)
*(Slide Deck Reference: Slide 15 | Direct Exam Relevance: Midsem & Endsem Question papers)*

The standard 8051 contains **128 Bytes of on-chip Data RAM**, addressed from `00H` to `7FH`. It is partitioned into three functional memory zones:

```
+--------------------------------------------------------------------------+
|                  8051 128-BYTE INTERNAL RAM MEMORY MAP                   |
+--------------------------------------------------------------------------+
| 30H - 7FH (80 Bytes)  | General-Purpose Scratchpad RAM                   |
|                       | (Variables, user buffers, application stack)     |
| --------------------- | ------------------------------------------------ |
| 20H - 2FH (16 Bytes)  | Bit-Addressable RAM                              |
|                       | 16 bytes = 128 individually addressable bits     |
|                       | Bit addresses: 00H to 7FH                        |
| --------------------- | ------------------------------------------------ |
| 00H - 1FH (32 Bytes)  | 4 Register Banks (8 registers R0-R7 each)        |
|   18H - 1FH           |   - Bank 3 (R0 to R7)                            |
|   10H - 17H           |   - Bank 2 (R0 to R7)                            |
|   08H - 0FH           |   - Bank 1 (R0 to R7)  <-- Default Stack Area!   |
|   00H - 07H           |   - Bank 0 (R0 to R7)  <-- Active on Reset       |
+--------------------------------------------------------------------------+
```

## 7. Register Banks (Banks 0–3) & Bank Switching Architecture
*(Slide Deck Reference: Slides 16–17 | Direct Exam Relevance: Midsem 2025 Q5c)*

The lowest 32 bytes of internal RAM (`00H` to `1FH`) are organized into **four distinct Register Banks**, each containing eight 8-bit registers designated `R0` through `R7`.

```
+--------------------------------------------------------------------------+
|                        REGISTER BANK MAPPING                             |
+--------------------------------------------------------------------------+
| Bank Select Bits  | Active Bank | RAM Address Range | Default Registers  |
|   RS1      RS0    |             |                   |                    |
| ----------------- | ----------- | ----------------- | ------------------ |
|    0        0     |   Bank 0    |    00H - 07H      | R0(00H) to R7(07H) |
|    0        1     |   Bank 1    |    08H - 0FH      | R0(08H) to R7(0FH) |
|    1        0     |   Bank 2    |    10H - 17H      | R0(10H) to R7(17H) |
|    1        1     |   Bank 3    |    18H - 1FH      | R0(18H) to R7(1FH) |
+--------------------------------------------------------------------------+
```

### 7.1 How to Switch Banks in Assembly
To switch banks, the programmer modifies bits `RS1` (`PSW.4`) and `RS0` (`PSW.3`):
```assembly
; Select Bank 0 (RS1=0, RS0=0):
CLR PSW.4
CLR PSW.3

; Select Bank 1 (RS1=0, RS0=1):
CLR PSW.4
SETB PSW.3

; Select Bank 2 (RS1=1, RS0=0):
SETB PSW.4
CLR PSW.3

; Select Bank 3 (RS1=1, RS0=1):
SETB PSW.4
SETB PSW.3
```

### 7.2 Midsem 2025 Q5c Tracing Analysis (The Bank Switching Problem)
*Problem Statement:* Trace registers after executing:
```assembly
        CLR   C
        MOV   R2, #04H
        MOV   R0, #40H
        MOV   R1, #50H
        SETB  PSW.3          ; Switch to Bank 1!
        MOV   R0, #60H       ; R0 of Bank 1 (RAM 08H) = 60H
        CLR   PSW.3          ; Switch back to Bank 0!
BACK:   MOV   A, @R0         ; Read from Bank 0's R0 pointer
        ADDC  A, @R1
        INC   R0             ; Increments Bank 0's R0
        INC   R1             ; Increments Bank 0's R1
        SETB  PSW.3          ; Switch to Bank 1!
        MOV   @R0, A         ; Write using Bank 1's R0 pointer
        INC   R0             ; Increments Bank 1's R0
        CLR   PSW.3          ; Switch back to Bank 0!
        DJNZ  R2, BACK       ; Loop 4 times
```
- In Bank 0: `R0` begins at `40H` and is incremented 4 times $\implies \mathbf{R0_{\text{Bank 0}} = 44\text{H}}$.
- In Bank 0: `R1` begins at `50H` and is incremented 4 times $\implies \mathbf{R1_{\text{Bank 0}} = 54\text{H}}$.
- In Bank 1: `R0` begins at `60H` and is incremented 4 times $\implies \mathbf{R0_{\text{Bank 1}} = 64\text{H}}$.

## 8. Hardware Stack & Stack Pointer (SP) Operation
*(Slide Deck Reference: Slides 18–19 | Direct Exam Relevance: Endsem 2025 Q1a)*

The **Stack** is an area of internal RAM used by the CPU for temporary storage of register data (`PUSH`/`POP`) and return addresses during `CALL` and interrupt events.

### 8.1 Stack Pointer (SP) Register
- The **SP** is an 8-bit register (located at SFR address `81H`).
- **Power-Up Reset Value:** $\mathbf{SP = 07\text{H}}$.

### 8.2 The Classic 8051 Stack Conflict (Exam Favorite!)
Because SP resets to `07H`, the very first byte pushed onto the stack will be written to:
$$\text{SP}_{\text{new}} = 07\text{H} + 1 = \mathbf{08\text{H}}$$
Notice that RAM addresses **`08H` through `0FH` belong to Register Bank 1!**
> **Exam Warning:** If your firmware uses Register Bank 1 and simultaneously uses the default stack without reallocating SP, **stack operations will silently overwrite Bank 1 registers (`R0`–`R7`)!** To avoid this, production code reallocates SP to scratchpad RAM:
> ```assembly
> MOV SP, #2FH    ; Stack now begins at 30H upwards!
> ```

### 8.3 Mechanics of PUSH and POP
- **`PUSH direct`:**
  1. Increment SP by 1: $\text{SP} \leftarrow \text{SP} + 1$
  2. Write data byte to address pointed by SP: $\text{RAM}[\text{SP}] \leftarrow \text{Direct Byte}$
- **`POP direct`:**
  1. Read data byte from address pointed by SP: $\text{Direct Byte} \leftarrow \text{RAM}[\text{SP}]$
  2. Decrement SP by 1: $\text{SP} \leftarrow \text{SP} - 1$

```
+--------------------------------------------------------------------------+
|                  STACK EXECUTION: INCREMENT-THEN-WRITE                   |
+--------------------------------------------------------------------------+
| PUSH:  SP = SP + 1  -->  RAM[SP] = Data   (Pre-increment)                |
| POP:   Data = RAM[SP] -->  SP = SP - 1    (Post-decrement)               |
+--------------------------------------------------------------------------+
```

> **CRITICAL SYNTAX RULE:** `PUSH A` is **ILLEGAL** in 8051 assembly! `PUSH` and `POP` require **Direct Addressing**. You must write `PUSH ACC` or `PUSH 0E0H`!

## 9. Machine Cycle Calculations & Time Delay Principles
*(Slide Deck Reference: Slides 31–35 | Direct Exam Relevance: All Midsem & Endsem papers)*

### 9.1 Machine Cycle Formulation
In a classic 8051 (e.g., AT89C51), **1 Machine Cycle = 12 Oscillator Clock Periods**.
$$f_{\text{MC}} = \frac{f_{\text{XTAL}}}{12}$$
$$T_{\text{MC}} = \frac{1}{f_{\text{MC}}} = \frac{12}{f_{\text{XTAL}}}$$

```
+--------------------------------------------------------------------------+
|                     CRYSTAL FREQUENCY COMPARISON TABLE                   |
+--------------------------------------------------------------------------+
| Crystal Frequency ($f_{\text{XTAL}}$) | Machine Cycle Period ($T_{\text{MC}}$) |
| ------------------------------------ | ------------------------------------- |
| **11.0592 MHz** (Standard UART)      | $12 / 11.0592\text{ MHz} \approx \mathbf{1.0851 \ \mu s}$ |
| **12.0000 MHz** (Exact 1 us)         | $12 / 12.0000\text{ MHz} = \mathbf{1.0000 \ \mu s}$       |
| **22.0000 MHz** (High-speed 8051)    | $12 / 22.0000\text{ MHz} \approx \mathbf{0.5455 \ \mu s}$ |
| **22.1184 MHz** (Double Baud)        | $12 / 22.1184\text{ MHz} \approx \mathbf{0.5425 \ \mu s}$ |
+--------------------------------------------------------------------------+
```

## 10. 8051 Parallel I/O Ports Architecture (P0, P1, P2, P3)
*(Slide Deck Reference: Slides 37–42)*

The 8051 contains 32 physical pins dedicated to four 8-bit bidirectional parallel I/O ports: `P0`, `P1`, `P2`, and `P3`. Each port is represented internally by an 8-bit latch located in the Special Function Register (SFR) address map.

```

Port 1: 90H (Bit-addressable: 90H - 97H)
Port 2: A0H (Bit-addressable: A0H - A7H)
Port 3: B0H (Bit-addressable: B0H - B7H)
```

## 11. Port 0 Open-Drain Structure vs. Ports 1–3 Internal Pull-Ups
*(Slide Deck Reference: Slides 38–40 | Direct Examination Relevance: Slide 47 Review Q1)*

University exam papers frequently ask why Port 0 behaves differently from Ports 1, 2, and 3.

```
       PORT 0 PIN ELECTRONICS                PORTS 1, 2, 3 PIN ELECTRONICS
       (Open-Drain Output)                   (Internal Pull-Up FET)

       +5V (Requires Ext Resistor!)          +5V
        |                                     |
       [R] (4.7k - 10k External)             [Internal Pull-Up FET]
        |                                     |
PIN ----+----- Drain of FET           PIN ----+----- Drain of FET
               |                                     |
          Gate-|-- Latch Q                      Gate-|-- Latch Q
               |                                     |
              GND                                   GND
```

### 11.1 Port 0 (Pins 32–39)
- **Circuit Structure:** Equipped with a pair of push-pull FETs, but the internal pull-up FET is turned OFF during general-purpose I/O mode. Thus, it functions as an **Open-Drain output**.
- **Hardware Requirement:** **Must be connected to external pull-up resistors** (typically a $10\text{ k}\Omega$ SIP resistor pack tied to $+5\text{V}$) to output a valid logic HIGH.
- **Multiplexed Mode:** When interfacing external memory, Port 0 dynamically outputs $AD_0 - AD_7$. In this mode, the internal push-pull drivers are active, so external pull-up resistors are not needed.

### 11.2 Ports 1, 2, and 3
- Equipped with **internal active pull-up resistors** (silicon FETs behaving as $\approx 20\text{ k}\Omega - 40\text{ k}\Omega$ pull-ups).
- They can directly output logic HIGH without any external pull-up resistors.

## 13. Configuring I/O as Inputs vs. Outputs & Read-Modify-Write Hazards
*(Slide Deck Reference: Slides 42–46)*

### 13.1 Configuring a Port Pin as an INPUT
Upon hardware reset, all ports are loaded with `FFH` (internal latches set to 1).
- **Rule:** To use any 8051 port pin as an **input**, software **must write a `1` to the corresponding latch bit**.
- *Why?* Writing a `1` turns OFF the lower pull-down MOSFET, leaving the pin pulled weakly high by internal/external pull-ups. An external sensor can now easily pull the pin down to 0V (logic 0) or leave it high (logic 1) without causing a short circuit!

```assembly
; Example: Configure Port 1 as input, read external switch data, and output to Port 2
        MOV P1, #0FFH    ; Configure all pins of P1 as inputs!
BACK:   MOV A, P1        ; Read physical logic state at P1 pins
        MOV P2, A        ; Output to LEDs on P2
        SJMP BACK
```

### 13.2 Read-Modify-Write (RMW) Instructions & Hazards
Instructions that modify port bits (e.g., `SETB`, `CLR`, `CPL`, `ANL`, `ORL`, `DJNZ`) do not read the external voltage at the physical pin. Instead, they read the **internal output latch flip-flop**, perform the modification inside the ALU, and write the new byte back into the latch.
- This prevents external electrical loading (e.g., a heavily loaded transistor holding a pin temporarily low) from accidentally resetting other bits in the same port latch!

## 14. The 5 Core Addressing Modes of 8051
*(Slide Deck Reference: Slides 48–57)*

An **Addressing Mode** defines how the CPU determines the memory location of the operands.

```
+--------------------------------------------------------------------------+
|                     8051 FIVE CORE ADDRESSING MODES                      |
+--------------------------------------------------------------------------+
| 1. Immediate Addressing        | MOV A, #55H     | Operand in instruction|
| 2. Register Addressing         | MOV A, R0       | Operand in register   |
| 3. Direct Addressing           | MOV A, 30H      | Operand at RAM address|
| 4. Register Indirect Addressing| MOV A, @R0      | Operand pointed by Ri |
| 5. Indexed Addressing          | MOVC A, @A+DPTR | Operand in ROM table  |
+--------------------------------------------------------------------------+
```

### 14.1 Detailed Breakdown of Each Mode

#### 1. Immediate Addressing Mode
- The operand value is a constant embedded directly in the instruction machine code.
- Preceded by the `#` symbol.
  ```assembly
  MOV A, #25H        ; Load immediate byte 25H into A
  MOV DPTR, #4500H   ; Load 16-bit address into DPTR
  ```

#### 2. Register Addressing Mode
- Operands reside inside the CPU working registers (`R0`–`R7` of the active bank), Accumulator `A`, register `B`, or `DPTR`.
  ```assembly
  MOV A, R5          ; Copy contents of R5 into A
  ADD A, R2          ; Add R2 to A
  ```

#### 3. Direct Addressing Mode
- The instruction specifies the raw 8-bit address of the internal RAM location (`00H`–`7FH`) or Special Function Register (`80H`–`FFH`).
  ```assembly
  MOV A, 30H         ; Copy content of RAM address 30H into A
  MOV 90H, #0FFH     ; 90H is the direct address of Port 1!
  ```

#### 4. Register-Indirect Addressing Mode
- A register is used as a **pointer** holding the address of the operand.
- **RESTRICTION:** Only **`R0` and `R1`** can serve as pointers for internal RAM! (Preceded by the `@` symbol).
  ```assembly
  MOV R0, #40H       ; R0 points to RAM location 40H
  MOV A, @R0         ; Load A with byte stored at address held in R0
  MOV @R0, #0FFH     ; Store FFH at RAM address 40H
  ```

#### 5. Indexed (Base-Plus-Index) Addressing Mode
- Used to access read-only lookup tables stored in Program ROM.
- Computes effective ROM address as $\text{Address} = \text{Accumulator (A)} + \text{Base Register (DPTR or PC)}$.
  ```assembly
  MOVC A, @A+DPTR    ; Fetch code byte from ROM at address (A + DPTR)
  ```

## 15. Look-up Tables via Indexed Addressing (MOVC)
*(Slide Deck Reference: Slide 56 | Direct Exam Relevance: Endsem 2025 Q3b)*

Look-up tables eliminate complex runtime calculations (e.g., trigonometric functions, squaring, BCD-to-7-segment conversion) by pre-storing results in ROM.

```assembly
; Program to compute squares of numbers 0 to 9 using a ROM Lookup Table
        ORG 0000H
        MOV DPTR, #SQUARE_TABLE
        MOV A, P1             ; Read input digit from Port 1 (e.g., 05H)
        ANL A, #0FH           ; Mask upper nibble (ensure 0-9)
        MOVC A, @A+DPTR       ; Reads ROM[DPTR + 5] = 25 (19H)
        MOV P2, A             ; Output square to Port 2
        SJMP $

        ORG 0500H
SQUARE_TABLE:
        DB 0, 1, 4, 9, 16, 25, 36, 49, 64, 81
        END
```

## 16. External RAM Access via MOVX
*(Slide Deck Reference: Slide 57)*

- When accessing external off-chip data RAM (up to 64 KB), the **`MOVX` (Move External)** instruction is used.
- Uses either 16-bit pointer **`DPTR`** or 8-bit pointers **`R0`/`R1`**:
  ```assembly
  MOV DPTR, #9000H
  MOVX A, @DPTR      ; Reads external RAM location 9000H (asserts RD pin)
  MOVX @DPTR, A      ; Writes A to external RAM location 9000H (asserts WR pin)
  ```

## 17. Bit-Addressable RAM & Special Function Registers (SFRs)
*(Slide Deck Reference: Slides 58–61 | Direct Exam Relevance: Endsem 2025 Q5b)*

The 8051 provides **128 individual bit addresses in internal RAM**, spanning RAM bytes **`20H` through `2FH`**.
- Each of these 16 bytes contains 8 individually addressable bits:
  $$16\text{ bytes} \times 8\text{ bits/byte} = 128\text{ bits}$$
  numbered continuously from **`00H` to `7FH`**.

```
BIT-ADDRESSABLE INTERNAL RAM MAP (20H - 2FH):
Byte Addr:   D7   D6   D5   D4   D3   D2   D1   D0
  20H:       07H  06H  05H  04H  03H  02H  01H  00H
  21H:       0FH  0EH  0DH  0CH  0BH  0AH  09H  08H
  22H:       17H  16H  15H  14H  13H  12H  11H  10H
  ...
  28H:       47H  46H  45H  44H  43H  42H  41H  40H  <-- Bit 42H is at 28H.2!
  ...
  2CH:       67H  66H  65H  64H  63H  62H  61H  60H  <-- Bit 67H is at 2CH.7!
  ...
  2FH:       7FH  7EH  7DH  7CH  7BH  7AH  79H  78H
```

### 17.1 Bit-Addressable Special Function Registers (SFRs)
Not all SFRs are bit-addressable. **The Golden Rule:**
> An SFR is bit-addressable **IF AND ONLY IF its hexadecimal byte address ends in `0H` or `8H`**.

| SFR Name | Byte Address | Bit Addresses | Bit Addressable? |
| :--- | :---: | :---: | :---: |
| **Port 0 (`P0`)** | `80H` | `80H` – `87H` | **YES** (Ends in 0) |
| **TCON** | `88H` | `88H` – `8FH` | **YES** (Ends in 8) |
| **TMOD** | `89H` | None | **NO** (Must access full byte) |
| **Port 1 (`P1`)** | `90H` | `90H` – `97H` | **YES** (Ends in 0) |
| **SCON** | `98H` | `98H` – `9FH` | **YES** (Ends in 8) |
| **Port 2 (`P2`)** | `A0H` | `A0H` – `A7H` | **YES** (Ends in 0) |
| **IE** | `A8H` | `A8H` – `AFH` | **YES** (Ends in 8) |
| **Port 3 (`P3`)** | `B0H` | `B0H` – `B7H` | **YES** (Ends in 0) |
| **IP** | `B8H` | `B8H` – `BFH` | **YES** (Ends in 8) |
| **PSW** | `D0H` | `D0H` – `D7H` | **YES** (Ends in 0) |
| **ACC (`A`)** | `E0H` | `E0H` – `E7H` | **YES** (Ends in 0) |
| **B** | `F0H` | `F0H` – `F7H` | **YES** (Ends in 0) |

## 18. Mathematical Conversion: Bit Address $\longleftrightarrow$ Byte Address + Bit Position
*(Slide Deck Reference: Slide 59 | Direct Exam Relevance: Endsem 2025 Q5b)*

### 18.1 Conversion Formulas for Internal RAM Bits (`00H`–`7FH`)
Given a Bit Address $B_{\text{addr}}$:
$$\text{Byte Address} = 20\text{H} + \lfloor B_{\text{addr}} / 8 \rfloor$$
$$\text{Bit Position } (D_0 - D_7) = B_{\text{addr}} \pmod 8$$

### 18.2 Exam Problem Verifications
1. **Locate Bit Address `42H`:**
   - Convert `42H` to decimal: $4 \times 16 + 2 = 66_{10}$.
   - Quotient: $66 / 8 = 8$ (which is `08H`).
   - Remainder: $66 \pmod 8 = 2$ (which is bit position $D_2$).
   - $\text{Byte Address} = 20\text{H} + 08\text{H} = \mathbf{28\text{H}}$.
   - **Conclusion:** Bit `42H` is bit **$D_2$ of RAM byte `28H`** (i.e., `28H.2`).
2. **Locate Bit Address `67H`:**
   - Convert `67H` to decimal: $6 \times 16 + 7 = 103_{10}$.
   - Quotient: $103 / 8 = 12$ (which is `0CH`).
   - Remainder: $103 \pmod 8 = 7$ (which is bit position $D_7$).
   - $\text{Byte Address} = 20\text{H} + 0\text{CH} = \mathbf{2C\text{H}}$.
   - **Conclusion:** Bit `67H` is bit **$D_7$ of RAM byte `2CH`** (i.e., `2CH.7`).

## 19. Solutions to All 4 Slide Review Question Sets

### Section 1 Review Questions (Slide 20)
1. *Size of the PC and of the SP register?*
   - PC is **16 bits** wide ($64\text{ KB}$ reach); SP is **8 bits** wide ($128/256\text{ bytes}$ reach).
2. *Power-up value of PC? Of SP?*
   - $\text{PC} = \mathbf{0000\text{H}}$; $\text{SP} = \mathbf{07\text{H}}$.
3. *Which register bank conflicts with the default stack area?*
   - **Register Bank 1** (occupying RAM locations `08H`–`0FH`).
4. *Instruction vs. directive — what's the difference?*
   - Instructions translate into binary machine opcodes executed by the CPU hardware at runtime. Directives are commands to the assembler tool during code assembly and emit no runtime opcodes.
5. *Find CY, AC, P after `MOV A, #0FFH` followed by `ADD A, #01H`.*
   - $\text{FFH} + 01\text{H} = 100\text{H} \implies A = 00\text{H}$.
   - Carry out of $D_7 \implies \mathbf{CY = 1}$.
   - Carry out of lower nibble $D_3 \to D_4 \implies \mathbf{AC = 1}$.
   - Count of 1s in Accumulator $A$ is zero (even number) $\implies \mathbf{P = 0}$.

### Section 2 Review Questions (Slide 36)
1. *Max count of a single DJNZ loop? Of a nested loop (2 counters)?*
   - Single loop: **256 iterations** (by loading register with `00H`).
   - Double-nested loop: $256 \times 256 = \mathbf{65,536\text{ iterations}}$.
2. *Are 8051 conditional jumps short or long? Consequence for range?*
   - All 8051 conditional jumps are **short relative jumps** (2 bytes). The target must reside within **$-128\text{ to }+127\text{ bytes}$** of the following instruction.
3. *Explain, with example, how CPU knows where to resume after RET.*
   - During `CALL`, the 16-bit address of the instruction immediately following the call is pushed onto the stack. Upon encountering `RET`, the CPU pops the top two bytes from the stack into the Program Counter ($\text{PCH}$ and $\text{PCL}$), resuming execution at the saved address.
4. *At 11.0592 MHz, compute delay of a loop running DJNZ 150 times.*
   - $T_{\text{MC}} = 12 / 11.0592\text{ MHz} = 1.0851 \ \mu\text{s}$.
   - `DJNZ` takes 2 machine cycles: $\text{Time per loop} = 2 \times 1.0851 = 2.1702 \ \mu\text{s}$.
   - For 150 iterations: $\text{Delay} = 150 \times 2.1702 \ \mu\text{s} \approx \mathbf{325.53 \ \mu s}$.
5. *Why is DS89C4x0 faster than classic 8051 at the same crystal frequency?*
   - Classic 8051 requires 12 oscillator clock cycles per machine cycle. The Dallas DS89C4x0 executes a machine cycle in **1 clock cycle** ($\approx 12\times$ faster).

### Section 3 Review Questions (Slide 47)
1. *Why does P0 need external pull-ups while P1–P3 don't?*
   - Port 0 has open-drain output transistors without internal pull-ups in general I/O mode. Ports 1–3 contain integrated internal pull-up FETs.
2. *State the reset value of all 4 ports; why does it matter?*
   - Reset value is **`FFH`** (all pins at logic 1). This ensures all pins default to safe, high-impedance input mode upon power-up.
3. *Set bit 5 of Port 2 without disturbing other bits.*
   - Instruction: `SETB P2.5` (or `SETB 0A5H`).
4. *List the alternate functions of every Port 3 pin.*
   - Detailed in Section 12 table (`RXD`, `TXD`, `INT0`, `INT1`, `T0`, `T1`, `WR`, `RD`).
5. *Write a program for a 25% duty-cycle wave on P2.4.*
   ```assembly
   BACK: SETB P2.4
         ACALL DELAY       ; High for 1 unit
         CLR  P2.4
         ACALL DELAY
         ACALL DELAY
         ACALL DELAY       ; Low for 3 units (Total period = 4 units -> 25% Duty)
         SJMP BACK
   ```

### Section 4 Review Questions (Slide 62)
1. *Which addressing mode is required for PUSH/POP? Why is PUSH A illegal?*
   - Requires **Direct Addressing Mode**. `PUSH A` is illegal because the opcode hardware specifies a direct RAM address field, not an accumulator register code. Must use `PUSH ACC` or `PUSH 0E0H`.
2. *Which two registers can be pointers in register-indirect mode?*
   - Registers **`R0` and `R1`** only (for internal RAM).
3. *Explain how MOVC A, @A+DPTR implements a look-up table.*
   - `DPTR` points to the table start in ROM; Accumulator `A` holds the desired index offset. The instruction adds the two, fetches the byte from ROM address $(A + \text{DPTR})$, and overwrites `A` with the result.
4. *How many bit addresses does bit-addressable RAM provide? Range?*
   - **128 bits**, spanning bit addresses **`00H` to `7FH`** (in bytes `20H`–`2FH`).
5. *Find byte address and bit position for bit address 5AH.*
   - $5\text{AH} = 90_{10}$. $90 / 8 = 11$ (`0BH`), remainder $2$.
   - $\text{Byte Address} = 20\text{H} + 0\text{BH} = \mathbf{2B\text{H}}$, **Bit position = $D_2$** (`2BH.2`).
6. *State bit addresses of P3.2 and P3.7; name their alternate functions.*
   - `P3.2` bit address is **`B2H`** (Alternate function: $\overline{\text{INT0}}$, External Interrupt 0).
   - `P3.7` bit address is **`B7H`** (Alternate function: $\overline{\text{RD}}$, External Data Memory Read Strobe).
